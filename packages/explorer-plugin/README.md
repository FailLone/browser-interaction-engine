# Independent explorer plugin

`@interaction/explorer-plugin` owns model routing, exploration scheduling, durable plans and follow-up rounds. It consumes the browser SDK's public methods. The SDK, core, browser adapter and existing client have no dependency on this plugin. Shared observation, operation and recovery semantics live in core/SDK; see [the host exploration contracts](../../docs/EXPLORATION-HOST-CONTRACTS.md).

## Install and enable

The workspace supplies the package. Use Node 24 and `pnpm install`. The existing server loads it only when `EXPLORER_ENABLED=true`. Copy the values from `.env.explorer.example` into your server environment; the server does not automatically read `.env` files. Then run `pnpm dev`, or `pnpm build` followed by `pnpm start`.

Keep keys on the server. `/plugins/explorer/v1/status` exposes only provider names, model names, configured flags and host capabilities. A blank task or a user-supplied structured plan starts without either model. Written natural-language instructions use JEV for intent classification; confidently exhaustive instructions need no LLM. LLM configuration is required only when the task needs structured interpretation, new inputs or new planning; a missing provider then saves the task with `configuration_required`. There is no implicit mock provider.

JEV configuration uses `EXPLORER_JEV_PROVIDER=typesafe|openrouter`, `EXPLORER_JEV_ENDPOINT` (full URL), `EXPLORER_JEV_MODEL` and `EXPLORER_JEV_API_KEY`. LLM configuration uses `EXPLORER_LLM_ENDPOINT` (full chat/completions URL), `EXPLORER_LLM_MODEL` and `EXPLORER_LLM_API_KEY`. Custom local endpoints may omit a key. For OpenRouter, `EXPLORER_LLM_PROVIDER=openrouter` enables explicit routing; `EXPLORER_LLM_UPSTREAM_PROVIDER` pins the upstream with fallback disabled and parameter support required. `EXPLORER_LLM_REASONING_EFFORT` accepts none/low/medium/high; `EXPLORER_LLM_MAX_OUTPUT_TOKENS` sets the completion budget. The example matches ui-sentinel’s current Alibaba route with low reasoning and uses 8192 tokens for structured exploration plans. See [OpenRouter routing](https://openrouter.ai/docs/guides/routing/provider-selection). The LLM endpoint must support JSON-object responses. Responses are also validated locally; unsupported formats fail explicitly.

The default routing policy is `program-first-v6`. Models supply missing semantics; they do not certify ordinary controls' expected functionality or approve every traversal step.

| Decision | Default policy |
| --- | --- |
| Task type | Blank input creates a full-page root in code. JEV classifies written instructions; specific targets or constraints require a structured LLM plan. |
| Next action / recovery | Code orders current SDK-executable candidates, prioritizes current internal work, and selects retained checkpoints for absent unfinished targets. Dispatch and recovery are revalidated by the host. No model ranking. |
| Regions / identities / discovery | Code partitions captured region candidates, keeps ambiguous historical identities independent, and visits SDK-offered bounded discovery targets. SDK-authorized hover/focus observation probes are attempted without risk-certification calls, with per-occurrence bounds and no click coverage. None of this grants historical replay or coverage. |
| Coverage | All members are retained without model calls. Only explicitly authorized representative sampling can ask JEV for a selection. |
| Ordinary supported controls | New plugin sessions opt into `executionPolicy: observed-ui` and use the matching guarded execution profile. Supported current operations need no model effect certification. Native submission, stale observations, identity ambiguity, boundaries, scope reviews and unknown outcomes remain host constraints. |
| Missing semantics | Once executable work is drained, weak candidate classification or a missing operation description can ask JEV; unresolved semantic interpretation can ask LLM for a bounded structured answer tied to captured evidence. Models cannot manufacture missing browser capabilities. |
| Input generation | Existing SDK options/samples are preferred. New semantic input content can use LLM. |
| End of round | Known blockers, budgets and capability gaps are preserved in code. Only unresolved semantic obligations can request JEV assessment of whether a new prerequisite plan is useful. |

An `unknown` business-effect classification is retained as unknown. Attempts explicitly record `effectsAssessment: not-assessed`, cannot automatically replay, and UI recovery reports `verificationScope: observed-ui`. A successful dispatch plus subsequent observation is interaction evidence, not a statement that the application behaved correctly. The default SDK and ordinary DFS policies are unchanged. Explicit `sessionOptions.executionPolicy: interface-only` retains legacy risk-review behavior; historical sessions are never silently reclassified. A policy change starts a fresh plugin round without clearing prior usage or evidence.

JEV/LLM calls remain cancellable and bounded by both request deadlines and the cumulative task budget. Model inputs, outputs, evidence references and their applied/rejected/stale consequences remain visible in the debug inspector. Deterministic steps emit program events (`action.selected`, `program.review`, `recovery.selected`, `plan.retained`) rather than fabricated model decisions. A missing model pauses only when an actual unresolved semantic request needs it. A provider failure retains the unfinished work; there is no hidden HTTP retry.

Tune gates against labeled examples of each judgment: missed in-scope controls, incorrect scope exclusions, incorrect operation permissions, ambiguity and changed observations. Track false exclusions, false grants, unresolved coverage, calls and actual cost on held-out examples; LLM agreement alone is not ground truth. Revalidate after changing model versions or prompts. Mock-provider regressions prove scheduling/guard behavior, not JEV accuracy.

Sampling and semantic prompts include accepted scopes and explicit exclusions, not the accumulated historical ledger. Model-only scope fingerprints are fixed-size hashes; exact bindings, evidence, unresolved obligations and prior attempts stay in persistence and remain subject to normal execution checks. HTTP failures retain the status and a normalized `context_limit` or `unspecified` category, never the error body. A context-limit failure pauses without retrying through LLM. Reviews and browser actions still run sequentially: advancing the page while a model is pending requires finer dependency validation and is not enabled by these optimizations.

When a permitted, unique, untested in-place action is already available, the scheduler defers replaying earlier entry operations until that fresh work is drained. Deferred branches remain in the plan and checkpoint stack, and necessary entries become eligible again afterward. The program emits `action.priority`; program scheduling records identify reentries as prerequisites, never new coverage. This prevents opening an old menu only to leave it for unrelated fresh work, without introducing concurrent model/browser execution or relaxing any scope/review gate.

Reentry retries are keyed to the accepted unfinished targets and prerequisite paths belonging to that entry. Completing unrelated work or adding duplicate ledger rows does not reopen an unchanged branch. Finishing a child or discovering a new child changes that branch's obligations and permits another freshly validated entry. These retry keys persist with the round; matching legacy keys remain honored, and no historical gap, budget or execution evidence is cleared by the change.

Unresolved purpose judgments are not repeatedly requested when only the control's screen position changes. The plugin keeps the original decision and observation references, emits `review.unchanged`, and retains the unfinished scope without granting or executing the operation. A changed task revision, document, URL, context, boundary, control size/content/structure, action basis or review status requires a fresh judgment. Successful authorizations are never stored in this unresolved-evidence cache. Model requests and browser mutations remain sequential.

## Embed

```ts
import { ExplorerPlugin, ExplorerStore, providersFromEnv } from '@interaction/explorer-plugin';
import { registerExplorer } from '@interaction/explorer-plugin/server';

const plugin = new ExplorerPlugin(engine,
  new ExplorerStore('.data/plugins/explorer.sqlite'), providersFromEnv());
await registerExplorer(app, plugin); // before app.listen()
// Existing app also keeps all standard engine routes.
```

The host is an injected `ExplorerHost` public-method interface. Inject a `Provider` implementing `decide(request, signal)` for an alternative service. Browser UI components are exported from `/ui`; `/client` exports a standalone HTTP client. Importing either browser entry does not load the server, SQLite or provider keys.

The plugin uses manual single-step execution, public review commands and checkpoint recovery. It does not invoke or patch the internal DFS loop. Application middleware owns the browser while a plugin run is active; competing writes are rejected. The standard pause/stop commands first pause the plugin. Read-only routes remain available. Embedders that bypass this middleware must provide equivalent single-writer ownership; direct SDK callers cannot be locked by an independent plugin.

## API

All endpoints are under `/plugins/explorer/v1`:

- `GET /status`, `GET /tasks`, `POST /tasks` (`url`, optional `goal`, `coverageMode`, `budget` and bounded `sessionOptions`). Omitted, empty or whitespace-only `goal` selects default exhaustive exploration with `coverageMode: all`.
- `GET /tasks/:id` returns the task, decisions and first event page.
- `GET /tasks/:id/events?after=0&limit=500` provides durable cursor pagination.
- `POST /tasks/:id/commands` accepts `start`, `resume`, `pause`, `stop`, `replan`, `continue-scope`, `extend-budget`, `accept-limitations`.
- `replan` accepts a new goal or reviewed `items`, and an optional `coverageMode` (`all` by default, `representative` only by user choice). `continue-scope` accepts existing `itemIds` and forces full traversal of those selected targets so they cannot be sampled out again. Pause before changing a plan. Start/resume separately after inspecting changes. `extend-budget` explicitly adds an allowance to the existing totals; it never resets usage. The UI labels this action “追加上方预算”.
- `accept-limitations` accepts `limitations: {codes: ["UNSUPPORTED_CANVAS"], reason: "User explicitly permits untested canvas contents"}` after pausing. Codes must correspond to retained, noncritical unsupported-content evidence. Accepted items remain `untested` with their original evidence; budgets, dispatch authority and unknown operation outcomes stay unchanged. This task-local choice persists across rounds and restarts. Explicitly selecting such an item with `continue-scope` removes its acceptance and requires fresh testing.

Plan scopes match exact URL, region label, control label, role, stable key, operation kind and optional value. Prerequisites use the same format. Ambiguous matches stay unresolved. A plan completion description is guidance; verification currently means successful supported interaction with a subsequent host observation, not arbitrary business assertions.

Unresolved control reviews use the observed accessible name (falling back to its explicit label), region, role and durable control key. Empty labels are omitted, and distinct same-name controls keep separate gaps when evidence provides distinct keys. These scopes can be selected for a later round without copying local control IDs or granting operation permission. Older gaps whose source controls were already merged remain unresolved; the plugin does not guess a target or rewrite historical success.

An older empty-label review record is enriched only when every retained source observation identifies one visible control with the same durable semantic scope; missing, conflicting or ambiguous sources and user-selected authority remain unchanged. A uniquely matched review gap may complete from a fresh, active host `display`/`container` classification only when no supported operation or outstanding operation review remains. `reviewResolvedBy` records this separately from execution evidence, with no action count or descendant coverage. Changed or revoked classification evidence reopens the obligation; explicitly selecting the scope for another round clears the completion reference and requires fresh review. The UI exposes both resolution and reopening as program nodes.

## Durable execution and coverage

Default totals are 3 rounds, 300 actions, 30 active minutes and 300 provider requests. Individual sessions default to 100 actions, capped by the task's remaining allowance. Recovery actions count through the host action ledger. Pauses do not consume duration; waiting for providers does. Already-dispatched host operations settle before ownership is released. A host recovery command may finish after the duration deadline; no further operation is dispatched afterwards.

Each new round rematches semantic scopes and obtains fresh reviews. Old successes may guide scheduling only when scope, declared context and captured dispatch bindings/constraints/options match. They retain their original session/attempt references and are never copied into the new engine audit. Missing or ambiguous targets remain unresolved. Unselected samples remain in the plan as untested, and do not automatically expand a later round. Users can select them explicitly for follow-up.

Extending the task duration does not change an existing host session’s original time limit. When that limit is reached, the plugin audits the current observation, preserves unfinished scopes and entry paths, and starts a fresh round within the remaining aggregate budget. It also handles a limit reached during dispatch preflight without treating the unissued command as an unknown execution. Unknown outcomes remain quarantined while independent work continues; no new plan generation is needed merely because a session expired. A paused task with no initialized plan cannot be completed by an empty-ledger audit. The timeline records `round.session_limit` with the host time usage and limit.

Tasks, rounds, decisions and correlated events are stored in a separate `explorer.sqlite`. Engine facts remain in the host's database. Model inputs and normalized results are persisted with observation references; relevant detailed evidence is pinned through the public evidence API and still subject to host storage limits. Keep both databases/evidence directories for historical inspection. An expired or missing artifact remains unavailable, rather than being replaced by current evidence.

On restart active tasks become paused, in-flight decisions become stale, and continuation observes again. A durable execute intent uses one request ID. Unknown outcomes are not replayed automatically. Missing public capabilities become explicit gaps. When the host exposes `boundaryExitMaterial`, the plugin can review an outside dismissal after current boundary work and normal exits are exhausted. Independent JEV Noul checks must support interface cancellation and reject external writes. The host binds the current point and preserves visible parent input/selection fields. `not_closed` leaves the boundary unresolved without retrying that point; `changed` or `unverified` blocks further dispatch, including after resume. A successful click alone never proves successful exit. Older hosts retain an explicit capability gap.

`create({url, evidenceBudget: {maxBytes, maxObservations}})` controls retained artifact capacity per session. Defaults are 1 GiB and 1,000 observations; the previous 128 MiB limit could stop large pages during review before meaningful traversal. Each model source observation remains protected, and capacity exhaustion is an explicit gap, never permission to delete protected evidence. Historical sessions keep their original quota; new rounds use the task setting or the new default. Action, time, round and model-request totals continue across all rounds.

The plugin gives observation a 10-second default window so a large page can produce multiple comparable captures. `sessionOptions.observeTimeoutMs` overrides it. This changes waiting time only: the host's stability checks and critical-gap gates remain in force.

A terminal unknown result from a supported, replayable native HTTP hyperlink in a clean session can be isolated into a fresh round. The original attempt remains unknown, its required scope remains unresolved, and the same source/destination pair cannot dispatch again, including after restart or plan edits. New rounds use new observations and reviews and share the original total budget. This continues independent work without claiming recovery or verifying the unknown navigation; other unknown operations, dirty sessions, missing outcomes and in-flight commands remain blocked. The timeline records `navigation.isolated` with the original evidence and destination. Program ordering uses captured navigation destinations to prefer in-page work before leaving it. Verified navigation from an ordinary button also retains the accepted source-page obligation. If a return reaches that page but cannot verify the old checkpoint, exploration may continue from the fresh observation only when no critical gap, unresolved execution or blocking boundary remains; `checkpoint_unverified` stays unresolved and is never converted into a successful restoration.

`completed` means the current observed plan is verified. `exhaustive` is always false. Discovery gaps, sampled-out members and unreachable states remain separately visible.

For accepted whole-page scopes, host `UNSUPPORTED_*` and `*_UNSUPPORTED` observations (such as canvas, iframe or shadow contents) create required capability gaps even when the host marks them noncritical. Other supported controls may still proceed. The plugin pins the source observation and emits `scope.unsupported` with the host's exact limitations. Neither a later unrelated success nor the last action at a budget boundary clears these gaps. Targeted control tasks do not inherit unrelated page-wide limitations. This records the host's boundary; it adds no browser access or new host capability.

Only an explicit user acceptance can make these unsupported-content gaps optional. The debug page offers “跳过此类能力限制（保留未测）” and records `scope.limitation_accepted` separately from execution results. Accepted limitations remain visible even when the current supported plan completes; they never count as successful coverage or justify a claim of absolute exhaustion.

## Debug UI and validation

`ExplorerWorkspace` integrates goal, budget, task selection and execution controls into the host sidebar, alongside a switch to the existing manual controls. Pass the host's selected `sessionId` so opening a historical session automatically loads its owning task without switching to a newer round. The traversal displays only the selected round's events and JEV/LLM counts, with a shortcut to the latest call. `ExplorerPlan` shows unfinished ranges and evidence in the main workspace. User-facing controls use exploration terminology without exposing the package boundary. The traversal column interleaves program, JEV, LLM and engine events. Click a decision to inspect input, output, LLM escalation reasons and actual application effects in the right-hand `ExplorerInspector`. Safe request bodies and response content are persisted without authentication headers or provider reasoning text. HTTP error bodies remain excluded. Applied plan/review/action/recovery events distinguish decisions from actual execution results; older records do not gain invented effects. Truncated output is retained for diagnosis but cannot execute. The UI does not invent a prose explanation for a JEV choice.

Tests use explicitly injected mock providers and real local Playwright pages. No real key or paid service is required. Live-provider acceptance is a separate final check after credentials are configured.

Older tasks without `coverageMode` default to full traversal for future reviews; existing recorded untested samples remain untested. Old decision records are not rewritten. When resuming a paused round made under an older policy version, the plugin starts a fresh session for current reviews and permissions; total budgets are not reset. The debug sidebar exposes the coverage choice and the decision inspector separates the raw model answer from the actual program resolution.

Execution authority is separate from the unfinished ledger. Only program-created exhaustive roots or accepted initial/user-reviewed scopes have `dispatchScope: true`; discovered action rows, follow-up suggestions and gaps are records, not new grants. Selecting a gap explicitly for a later round grants that selected scope. Old tasks restore authority from the last persisted initial/revised plan snapshot, never from accumulated page-level gaps. If that snapshot is unavailable they require replanning. Reviews target controls relevant to authorized scopes or prerequisites. Once all explicit goals have execution evidence, the scheduler audits completion before attempting recovery; checkpoint matching uses semantic scopes and the source observation rather than exact equality of scope objects with different optional fields.

While a dialog, menu or other active boundary is open, review scheduling prioritizes that boundary as well as action execution. Background control/group reviews and page-wide discovery wait until exit; they are not marked reviewed or removed from the plan. Region grouping prefers the current boundary and uses the host's public incremental review contract when available. Models receive region semantics and control evidence; exact dispatch and reuse bindings stay with the host for validation instead of being duplicated in the grouping prompt.

Current boundary exits use an attempt cache for the observed boundary visit. A boundary appearing after an observed closure or in a new document may require the same exit operation again, even if that operation already has historical success. An unchanged boundary does not reset the cache, so an ineffective exit is not retried indefinitely. The current scope, risk, identity, unique-target and host preflight guards still apply; every repeated exit is a new recorded action under the same total budget.

An operation-only scope (for example `kind: select, value: IOC`) must bind to a current candidate before control review; it never implies page-wide scanning or scrolling. User-named future controls remain semantic targets with prerequisites until observed. Unique concrete operation scopes can complete immediately on successful dispatch and subsequent observation; broad scopes still require auditing all observed cases. Completed scopes no longer request unrelated reviews.

## Task intent and default exhaustion

`plugin.create({url})` needs no natural-language task and no initial model call. After observing the initial page (including redirects), the program creates the authoritative root `{url: observation.url}`. It covers new controls, menus and dialogs appearing at that same URL. This is current-page interaction exploration, not automatic whole-site navigation or visual-defect inspection. `exhaustive: false` still means that finishing the recorded scope is not a proof of absolute site exhaustion.

For nonempty instructions, the `task-intent` JEV Choice returns `exhaustive`, `targeted`, `unsupported` or `uncertain`. Only confident unrestricted `exhaustive` directly creates the root. Specific operations, regional scopes and explicit exclusions need a structured plan; unclear classifications also use this interpretation path. Unsupported classifications stop without executing. UI events preserve the JEV answer, routing choice, resulting intent, source and program-created scope. A natural-language classification can be mistaken; recorded intent is visible for review and these thresholds are provisional.

When needed, one LLM generation returns a strict discriminated schema (`initialTaskSchema`, exported by the plugin):

```json
{"mode":"exhaustive","boundary":"current-page","exclusions":[]}
```

```json
{"mode":"exhaustive","boundary":"current-page","exclusions":[{"scope":{"label":"Delete","kind":"click"},"instruction":"do not click Delete"}]}
```

```json
{"mode":"targeted","items":[{"title":"Open settings","scope":{"label":"Other settings","kind":"click"},"prerequisites":[],"completion":"Dialog appears","required":true,"reason":"Requested operation"}]}
```

The other variant is `{"mode":"unsupported","reason":"..."}`. Unknown variants/fields, empty target plans, page-wide exclusions and exclusion quotes absent from the user's instruction are rejected before execution. Exclusions are constraints, remain visibly untested, and override automatic navigation/exit candidates. A model cannot supply an `items` subset for an exhaustive root. Both exhaustive paths require full coverage mode; representative sampling must be an explicitly targeted task, not a silent interpretation of exhaustion.

The original goal remains unchanged (blank stays blank). `Task.intent` persists version 1, mode and source (`default`, `jev`, `llm` or `user`); exhaustive intent also carries its actual page URL and exclusions. Clearing the task and replanning restores the program default. Explicit plan edits or selected-range supplementation become targeted intent. Historical tasks retain their existing plans and do not gain invented intent metadata. All resumes and revisions preserve accumulated budgets.

The sidebar starts empty and explains its default. The timeline shows “判断任务类型”, “程序建立全页范围” and structured intent effects alongside model requests. “LLM 0 次” is accurate for JEV/program-only runs; input generation or shared-purpose descriptions may still require LLM later.

Task-type-triggered generation records `Decision.triggeredBy`, linking the LLM input/output back to the JEV classification. This is a deliberate generation request rather than the router's legacy confidence fallback. Starting a new task releases idle/paused sessions belonging to completed plugin tasks through public `stop`; ordinary and unfinished sessions remain protected.

Scope completion is audited even when the last permitted action just revealed a new dialog or control. Pending actions, classification/identity/operation reviews, region assignment, discovery limits and critical observation gaps prevent a broad scope from inheriting completion from one successful action. These checks emit `scope.audit`; newly observed unexecuted actions stay in the unfinished plan.

Unexecuted action gaps retain the observed entry path, including gaps discovered immediately at a budget boundary. A later selected supplement can reopen that path under fresh reviews. Continuing an authorized broader scope can also reenter for its unfinished child records, but the record itself grants no new authority: the current action must still be permitted by an accepted scope or explicit prerequisite. Previously observed background siblings keep their original frame path instead of inheriting the opener of a foreground dialog.

The within-round no-progress guard includes completed review keys, bounded evidence refreshes and completed semantic clarifications. Reviewing a different unresolved control is progress even when the DOM, pending host queues and deduplicated gap labels stay unchanged. Repeating the same drained work does not advance these keys; total budgets and the cross-round unchanged-gap guard still apply. Progress accounting does not rebuild the host's pending review queues after every step. Reviews, dispatch preflight and completion audits still read current host material; this removes redundant reads without caching permissions or weakening the completion audit.

Clear classifications from the same observation are submitted through the public `classifyControls` command in batches of at most five. Each target still has its own model request, answer and evidence; batching reduces repeated host captures, not the required judgments. An uncertain target waits for the prepared classifications to be submitted and the page recaptured, then is judged again. Prepared answers are never submitted after cancellation or an observation change, and are recorded as cancelled/stale rather than applied. Every accepted member links to the batch command and its contributing decision IDs in the inspector. Browser execution remains sequential with model review.

Region judgments use the same guarded batching approach: up to five candidates from one observation, with separate model decisions and disjoint unassigned control sets, are submitted through one public `reviewRegions` command. Only one region receives an unassigned page-traversal responsibility, and valid existing regions remain through incremental updates. Uncertainty flushes the earlier clear regions before refreshing; cancellation or stale observations discard the entire prepared batch. This reduces host captures without reusing grants or running browser mutations while models are pending.

Controls whose operation purpose remains unresolved can receive a bounded hover/focus probe even after an `interaction` classification. Classification alone never authorizes it: a separate JEV checklist must positively establish a useful interface observation and reject an external/business write for the selected probe kind. Uncertainty retains a gap, with no ranking fallback. Each current element is probed at most once per document and round. Scope exclusions and active boundaries still apply, and host preflight validates the current node and observation.

Probes use the public command interface with a durable request intent, action-budget accounting and recorded before/after observations. Unknown outcomes or missing execution records block further dispatch across restart; probes are never isolated as replayable hyperlink navigation. Pause waits for an issued command and prevents subsequent actions. A successful probe supplies observation evidence, never click coverage or permission. Existing obligations and checkpoints are retained before dispatch, and newly revealed work carries the observed hover/focus prerequisite; this does not promise that the host can replay that path. Missing probe capability remains a gap while other supported work continues. The inspector links the JEV input/output to the probe request and actual result, explicitly distinguishing it from click coverage.

Checkpoint recovery judgments include the current and historical URLs, contexts, boundaries and region summaries, accepted scopes, unfinished targets and their current availability, plus the recorded entry prerequisites. A blank task supplies the same full-page objective as other judgments. The prompt shows at most 50 target descriptions with explicit total/omitted counts; all remaining branches stay in the traversal stack. An uncertain judgment records a deferred recovery effect. An accepted judgment only requests public host recovery: the host still decides whether an allowed return path exists, verifies it, and accounts for any actions. Historical targets never count as current execution evidence.

Fixed full-coverage decisions are applied in batches of at most 50 groups through `decideExplorationGroups`, with current task/observation and group-revision guards. `scope.retained` records program provenance, current member references and historical-member counts; it does not grant operation permission or mark members executed. A rejected stale batch remains eligible for fresh review. Sampling prompts include accepted scopes and user exclusions, not the accumulated historical gap/evidence ledger; the full ledger remains persisted for inspection and follow-up.

Repeated-record scopes consume the SDK's `browserControlCorrespondence` hint. The adapter owns record, template, slot and control conditions; document-local owner/row instance IDs are excluded. The historical opaque key format remains readable. URL, region, label, operation and value constraints still belong to the task, and colliding semantic scopes remain unresolved rather than selecting an arbitrary occurrence. A matching hint grants no identity or replay permission. The core `operationCorrespondence` query verifies retained successful evidence and current operation conditions before the plugin uses history for scheduling; it never writes a success in the new session. On resume, legacy scopes are converted only when retained original observations establish the exact old key and scope; missing or conflicting evidence leaves them unchanged. `scope.remapped` records the before/after constraints and source evidence. Attempt caches, budgets and unknown-outcome quarantine are preserved.

For controls without a host stable key, the plugin also uses the public `identityContext` scope/binding as a matching hint, together with control semantics. This distinguishes same-name fields with different observed descriptions without using current values, positions or execution IDs. These hints do not replace existing keys or missing list-record identity; identical contexts still collide and remain unresolved. Attempt tracking uses the same distinction, and planning/ranking receive the captured context paired with the exact candidate scope. Legacy unbound scopes are not silently narrowed, and historical success is never copied into a fresh session's execution audit.

A coarse historical gap does not replace the separate records for distinct current operations. Each unambiguous candidate keeps its exact scope and original attempt evidence, so completing one field cannot suppress another or trigger needless replay in a later round. Equivalent unfinished rows settle together only after all known members in current and retained source observations are verified, allowing their parent scope to settle without another round. Missing source evidence, disappeared untested members, unknown outcomes and capability gaps remain unresolved; a later successful action cannot rewrite an earlier unknown outcome.

When public observation reports a new document instance after reattachment, the round clears its old attempted-action cache along with traversal frames and review keys. The task ledger, unknown-outcome quarantine and aggregate budgets remain intact, so a reopened interface exit can be reviewed and executed again without replaying an unknown submission. Boundary-exit preservation counts actual inputs (including empty, unchecked and read-only fields), stateful ARIA controls and observed selections; the default `checked: null` and `selected: []` fields on ordinary links/buttons do not consume the 100-control preservation limit.

## Observation storage

The SQLite host store uses schema v3. Large observations can reference immutable, content-addressed control, region and nested JSON fragments held in compressed packs. Each observation retains its own ordered reconstruction manifest, metadata and full-content digest. A bounded admission hint selects whole-value gzip when sharing would mostly add new objects. This chooses an encoding only: controls, inputs, property order, execution evidence and distinct observations retain their original values. Plain JSON and schema-v2 gzip rows remain readable. Older binaries reject the new database version; back up before upgrading.

For an idle, backed-up store, `compressObservations({cursor, limit})` still migrates old plain rows to whole-value gzip in bounded transactions. `observationStorageStats()` reports manifests, shared objects, packs and unused ranges. `garbageCollectObservations({repack:true})` verifies every retained observation root before collecting unreferenced objects or repacking mixed packs; it never deletes observation roots by age. Explicit `compact()` returns freed SQLite pages to the filesystem. Startup does not bulk-migrate observation payloads or vacuum.

Prefer the public `get`/`list` methods. SQL consumers must select `kind, id, session_id, json, compressed_json` and call the bound `store.decodeStoredEntity(row)` inside `store.transaction`, including the row query in that transaction. The bound decoder resolves shared objects from one consistent snapshot. Standalone `decodeStoredEntity` continues to read plain/gzip rows, but structural rows require an object resolver. The JSON envelope alone is not an observation.

File evidence publication and collection coordinate across cooperating instances/processes through an OS-backed SQLite lock. `deleteMany(keys)` scans remaining manifests once per batch; collection rejects malformed or missing references before deleting blobs. Logical file deletions can partially finish if an I/O failure interrupts a batch. The retention layer therefore does not claim successful release after a rejected deletion. Normal generated evidence keys are unchanged; new writes/deletes reject the reserved `.coordination`, `blobs` and `*.meta.json` names, and the store also rejects reads through those reserved keys. Older arbitrary keys in that namespace require an explicit offline migration. Business retention metadata still assumes one engine writer; this file lock does not make concurrent pin changes and deletion atomic.

This reduces retained observation payloads, not a global storage quota. Artifact limits remain per session; plugin model records and non-observation entities have their own growth. Monitor aggregate storage and retain an explicit backup/retention policy for concurrent pages. No protected or unknown-result evidence is deleted to satisfy a quota.

## Task storage

ExplorerStore schema v4 keeps active plan items and the current round directly addressable. Settled plan items and older rounds are packed into bounded, integrity-checked Zstandard blocks; large task headers are compressed with a small query projection. The record codec shares JSON key schemas and repeated string values inside each block. Persistence occurrence handles remain separate even when business IDs or values coincide. All public reads reconstruct independent task values; compressed data grants no execution or coverage authority.

The v1–v3 upgrade is atomic and validates ordered items before converting their representation. Back up before opening with the new binary; the format is not writable by older binaries. CAS writes publish headers, occurrence rows and block references together. `taskState()` obtains the full task and editing handles in one assembly pass. Active queries use indexed projections and decode the returned items; full reads validate every retained task item. Pending dispatch, unknown outcomes, source evidence, budgets and task versions retain their meaning across migration and restart.

Regular writes avoid a full-history block collection. For an idle, backed-up task store, call `compactTaskStorage()` to validate roots, repack retained values and remove unreferenced blocks; its result records removed block IDs, hashes and sizes. Add `{reclaim:true}` to return freed pages to the filesystem. Maintenance retains logical task versions and occurrence handles. Decisions and event audit records are not deleted by this operation. Compression does not imply that every workload is faster: measure full reads, hot writes, maintenance and actual DB/WAL bytes separately.
