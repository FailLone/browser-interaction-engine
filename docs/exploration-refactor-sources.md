# Exploration refactor: source references and boundaries

Reviewed 2026-10-16. This work reuses established design ideas in the existing TypeScript architecture. No upstream implementation has been copied, translated or vendored, and no additional crawler framework is installed. The Java/Selenium graph and fragment implementations are closely coupled to their own browser, event, DOM and visual comparison models; copying a small-looking method would import those assumptions without their surrounding invariants.

FRAGGEN's fragment similarity is not proof of business equivalence or replay safety. Its discussion of very small fragments and near-duplicate actions matters: a narrower projection can improve reuse while still hiding distinct functionality. This implementation therefore does not use a similarity score to authorize execution or discharge an arbitrary UI branch.

## Bounded source conditions for operation samples

`packages/adapter-playwright/src/branch-conditions.ts` adds `browser-branch-conditions-v1`. It samples observed checked, selected, pressed and expanded states in the target's captured native form, declared component ancestry or semantic region. Portable keys exclude document and node instance identifiers. Stable target bindings, selector semantics, form ownership and selected option values remain significant. Passive quote/time text and free-text input starting values do not generate new mode samples. The target's own fill/select/check starting state is omitted because the requested destination value is already part of the operation sample.

The projection has a maximum of 32 relevant selectors. It declines sample equivalence for ambiguous selector bindings, unresolved instance-only selectors, unsettled selector evidence, missing required selection state, unknown declared context, critical capture gaps, or overflow. For example, an empty `selected` array alone does not prove `aria-selected=false`; captured component membership retains that distinction. It never silently truncates those conditions. A changed semantic target/binding remains a distinct operation through the existing target shape and correspondence rules. The observation canonical, identity matching, target readiness and execution permission remain separate.

This is **observed condition sampling**, not causal dependency inference or exhaustive combination generation. Native form isolation and declared group/region relationships are the available structural evidence. Hidden JavaScript dependencies spanning otherwise unrelated components still require declared context rules or stronger future dependency evidence. Distinct forms do not invalidate each other's samples just because they share a `main` region; an explicitly shared component can express cross-form locality. Disjoint semantic regions are not made related merely by a common `main`/document ancestor; a selector in the target's actual containing region is related. A page without semantic partitions conservatively uses its unpartitioned region, subject to the evidence bound.

Coverage policies are versioned (`browser-controls-live-v4`, `browser-controls-correspondence-v2`, `browser-native-record-link-operation-v2`, `browser-representative-v2`). Original observations and attempts are not rewritten. Current correspondence re-evaluates both source and target facts under the same current policy. Per-round scheduling keys include the mode condition and captured semantic owner/binding when present, while retaining their legacy encoding for controls with neither related modes nor semantic binding evidence. Missing mode evidence uses a stable unverified scheduling marker instead of claiming equivalence; passive whole-page text changes cannot renew that retry key. Existing scheduling keys or a pre-upgrade completed plan row alone are not sufficient proof for the new source-condition sample. A first upgraded round can therefore receive new scheduling revisions; only current SDK correspondence, not an old retry hash, proves historical coverage.

## Validation scope

`tests/branch-conditions.test.ts` uses a separate ephemeral HTTP fixture, browser and in-memory store. It executes the same button in two real form modes and verifies different rendered branches and rejected cross-mode coverage. It checks quote ticks, unrelated forms, fresh documents, changed bindings, and conservative refusal on incomplete/ambiguous/overflow evidence. These tests establish the bounded contract; they do not establish real-site exhaustion, absence of nonlocal dependencies, or production recovery success rates.

`tests/explorer-source-conditions.test.ts` exercises the plugin scheduler against a separate real browser with a temporary test database: an open exploration scope executes the A and B branches in one round, then returning to A reuses its verified history without redispatch. Another case retains both successful sources in a legacy plan row and verifies that a source whose actual outcome becomes unknown cannot supply coverage. A shared-key, same-name button rebuilt under a changed semantic owner receives fresh work; another rebuild under the unchanged owner does not. The finite fixture deliberately keeps an unavailable target pending; it does not reinterpret a completed one-shot user action as a continuous monitoring request.

Further evaluations should count verified target arrivals separately from full checkpoint equality, preserve unknown outcomes, report active obligations separately from historical rows, and compare useful new branch observations against recovery and initialization costs. A queue becoming empty is not an exhaustion oracle.

The [target-arrival follow-up](experiments/target-arrival-fix-2026-10-16/README.md) freezes product commit `1ed2238` and reruns the same 160 trials. Native hidden descendants no longer certify arrival. Target-directed intermediate steps use source-operation evidence and dispatch guards instead of whole-page equality; strict checkpoint replay retains canonical checks. Both static and changed-quote nested targets produce actual SDK inputs in 5/5 trials. The undeclared nonlocal-dependency negative control still fails, so local operation evidence must not be presented as a complete causal model.

The native SDK `controls` queue retains its existing encountered-control traversal sampling and does not enumerate mode combinations. `controlsTraversalCase` serves that legacy queue only; the independent explorer plugin owns condition-specific branch discovery and budgets. SDK `correspondenceCase` and coverage reconciliation remain condition-specific and reject unavailable dependency evidence. An attempted queue row keeps its actual source observation, so an A execution is historical evidence at A, not proof that an unexecuted B mode succeeded. The control-coverage report explicitly counts encountered control operations rather than every value/state combination.

## Observed route revisions

`reentry-evidence.ts` retains the source operation's scheduling condition plus captured replay/risk/basis metadata. `routeKey` omits direct attempt/observation references and known review proof-reference fields. Named boundaries with captured type and region are compared semantically, so the same native route into a named dialog in a fresh document does not produce another route revision merely because its boundary key changed. Different source modes and policy revisions remain distinct even if their visible entry/target names match. Incomplete boundary evidence falls back to exact keys; opaque review condition hashes and unknown evidence rules retain their facts conservatively and may produce extra revisions. Erasing those conditions could suppress a newly valid source. Those stored fields never grant repeat permission: the host must reassess the original successful attempt against the current observation.

`routeFinder` accepts an optional first-edge predicate. A currently rejected historical route A therefore cannot hide an equivalent-looking route B whose actual source is verified for the current mode. Only the first edge is checked against current browser facts: nested edges are revalidated when reached, and the default historical path lookup keeps its existing behavior. Tests in `explorer-route-revisions.test.ts` use real source attempts and SDK repetition assessment, preserve per-mode retry debt across A–B–A, and invalidate permission during the awaited checkpoint call to verify that traversal cannot silently become a fresh execution.

## Incremental recovery and storage follow-up (2026-10-17)

The [measured follow-up](experiments/incremental-recovery-2026-10-17/README.md) additionally inspected Playwright's pinned [`snapshotterInjected.ts`](https://github.com/microsoft/playwright/blob/v1.58.0/packages/playwright-core/src/server/trace/recorder/snapshotterInjected.ts): unchanged nodes reference a prior snapshot/node, with cache invalidation for changed facts. This informs sharing rather than browser-state restoration; the Playwright collector was not copied or introduced here.

[restic's storage design](https://restic.readthedocs.io/en/stable/100_references.html#backups-and-deduplication) explains content-defined boundaries that resynchronize after insertions. Our independently implemented bounded Gear-style splitter uses small, independently hashed evidence blocks in the existing v3 manifest; it does not copy restic's Rabin implementation or backup-sized chunks. Reconstruction does not require a parent snapshot or an unbounded patch chain. Task rows are normalized separately and retain ordered occurrences; byte deduplication never grants control or operation equivalence.

Crawljax's distinction between a desired destination and observed replay outcomes informs bounded alternatives in core. Each selected route starts at the actual current observation and retains SDK replay/arrival checks. Failed paths are evidence, not authority to discard pending work. This is not a wholesale port of Crawljax's search or FRAGGEN's visual approximation, and it does not yet implement reliability-weighted global routing. No upstream code was copied, translated or vendored.
