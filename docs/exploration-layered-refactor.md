## 判断与范围

采用分层重构，当前置信度中等。现有 SDK 已有状态图、检查点路径、恢复验证、未知执行处理和覆盖对应机制；没有证据支持替换整套执行器或自动化框架。主要缺口是这些契约之间的连接，以及调度把历史目标、当前位置和严格画面一致性混用的部分。独立实验已经证明部分收益，也发现了新的到达验证回归，当前实现尚未通过验收。

base 的分类复用保留。分类证据只能关闭分类审阅工作；历史执行对应才能支持覆盖继承；重复执行还须获得当前重放许可。三者都需要当前证据，不能互相授权。

本阶段不声称任意网页可恢复或穷尽。认证存储恢复、DOM/截图回放和可继续交互的页面恢复是三件不同的事。浏览器上下文和存储状态不能还原任意 JS 堆、外部业务状态及所有历史事件。

## 实际分层及变化

| 层 | 已有基础 | 本阶段变化 |
| --- | --- | --- |
| core | 观察、状态/转换图、路径记录、严格 `reachCheckpoint`、执行队列、未知结果账本 | `explorationTargetCorrespondences` 对应未执行历史目标；`reachExplorationTarget` 复用恢复策略并单独验证目标到达；重复执行来源在队列派发和异步校验后再次检查 |
| 浏览器适配器 | 身份匹配、控件与操作采样、边界和局部恢复步骤、覆盖对应 | 有界的相关模式投影；目标条件与目标自身就绪验证；操作调度键纳入语义绑定 |
| SDK 组合 | 分类/覆盖证据、审阅、恢复评估、继续探索 | 目标到达报告独立的 `dispatchAvailability`；继续尊重已验证恢复记录和未知结果 |
| 独立探索插件 | 计划、DFS 工作帧、模型路由、跨轮证据和预算 | 当前观察位置与保留工作分离；条件化任务、持久化恢复重试；所有历史成功来源参与 SDK 核对；未完成记录的派生生命周期视图 |

调用链为：插件选择未完成目标 → SDK 目标恢复 → 既有边界退出/历史返回/状态图路径/局部逆操作/起点重放 → 重新观察并核对目标 → 插件从实际观察继续审阅和调度 → 原有执行约束再次校验。

`TARGET_REACHED` 表示至少一个请求目标具有唯一、就绪的当前对应，结果同时列出具体匹配。它固定返回 `checkpointVerified:false`、`currentExecution:false`、`executionAuthorized:false`，不保证请求中的所有目标均已出现。严格检查点一致性仍使用原接口。返回后区域审阅未完成时，可以确认目标出现，实际派发仍被审阅约束阻止。

原 `reachCheckpoint` 验证的是可观察检查点，不会清除未知执行结果。插件在恢复前后、轮次结束和重启入口核对原会话账本；即使该接口报告画面到达，存在未知结果时也记录为 `UNVERIFIED` 并保留原始返回值用于审计。只有关联原执行记录的已验证 continuation 才能解除阻断，并给对应路由一次新的恢复机会；原 attempt 的 unknown 状态保持不变，旧数据缺少来源映射时继续保守阻断。

恢复发生实际动作、文档变化、上下文或边界变化后，插件记录浏览器的真实位置。失败不会弹掉待处理帧，也不会把旧计划路径写成已验证当前位置。严格恢复成功才恢复对应父路径；目标恢复成功保留尚未处理的历史目标。

## 关键不变量

1. **状态、身份、操作分别判断。** 完整观察仍保留动态文字；覆盖操作投影只忽略不参与绑定的被动文字。相同名字或共享稳定标识不足以对应不同语义所有者。
2. **模式变化是新样本。** 同一表单、声明组件或相关语义区域的 checked/selected/pressed/expanded 状态进入源条件；不同表单和无关区域不互相失效。自由文字初值和被动报价不生成模式组合。最多 32 个相关选择器，歧义、关键缺口、未知上下文或超限时拒绝等价，不截断成“成功”。投影不可用时采用稳定的未知条件调度标记；整页价格变化不会刷新尝试额度，已知模式或语义绑定变化仍会产生新键。
3. **重复有单独权限。** 路由记录需要真实成功转换。重复来源必须可重放、操作条件对应且当前可执行；未评估业务效果的旧动作不能因新会话出现而自动改为可重放。目标重放在每步执行前校验，目标出现时可以提前结束；中间路径仍保守要求既有状态验证。
4. **历史成功不冒充本轮执行。** 多个模式的成功 attempt 全部保留，最新 `resolvedBy` 不覆盖旧证明。SDK 每次重新判断适用性。未知结果不作为成功来源，分类成功不作为动作成功。
5. **原始账本与当前调度视图分离。** 活动、等待、不可达、历史对应组只提供工作视图。原计划行、发现证据、未知结果、恢复缺口和未支持能力保留。历史别名不能让任务自动完成。
6. **重试需要条件变化或新覆盖。** 同一语义恢复目标的条件版本不能因观察 ID、检查点 ID、重启或价格变化而刷新。A→B→A 不自动恢复 A 的额度；检查点恢复重试账每条路线最多保留 16 个条件版本，未知执行保持锁定，除非对应原执行得到明确的 continuation 验证。必要菜单重入另有按相关条件和新子覆盖记录的额度。框架仍受任务总动作/时间预算约束。

观察与对应缓存只在一次同步查询内复用；跨 await、审阅更新或新观察后重建。生命周期历史观察缓存最多 8 份，SDK 对应请求每批最多 16 项。生命周期在轮次审计更新，UI 明确标为“最近轮次审计”，不把过期快照显示成当前实时结果。当前历史对应组仍依赖目标在观察中可对应；离开该页面后，旧别名可能重新成为独立等待项。因此本阶段没有证明跨页面、跨轮的未测集合或存储体积收敛。

## 与替换架构的比较

| 方案 | 收益 | 成本与迁移风险 | 能力边界 |
| --- | --- | --- | --- |
| 本次分层重构 | 复用已有图和证据；将到达、覆盖、执行权限分开；保留旧任务和审计来源 | 新字段向后兼容，但旧发现行可能缺条件键，须保守核对；策略版本更新会使部分旧证明失效并增加一次审阅 | 无完整 JS 快照；非局部依赖需额外规则；历史持久化仍增长 |
| 改成显式图优先任务调度 | 可统一跨轮路由代价、失败退避和目标优先级；减少 DFS 位置依赖 | 需要迁移任务/边/条件与预算，验证调度公平性；仍可复用本次 SDK 契约 | 图只覆盖已观察状态和已验证路径，未知 UI 分支仍需发现 |
| 替换为 Crawljax/FRAGGEN 或其他执行器 | 可获得已有爬取队列或分块算法 | Java/Selenium/DOM 模型、身份、风险、证据和插件接口需整合；双栈长期维护成本高 | 相似状态不等于业务等价；换框架不能获得任意快照还原，也不能解决未知副作用 |

## 小规模验证与验收口径

先在可控网页上固定 6 类场景，每场景至少 10 个独立会话、3 次关闭插件后接续；再对固定 OKX 起点做基线/改造各 5 轮相同预算对照。真实站点试验需单独隔离测试会话，不接管现有主线程的浏览器。

| 场景 | 必须验证 |
| --- | --- |
| 嵌套菜单 | 父/子菜单路径来自真实转换；完成一个子分支后能到达另一个；无子进展不循环打开 |
| 弹层退出与重入 | 退出验证失败保留实际边界；必要重入有来源证据；一次性引导消失不强求旧整页相等 |
| A/B 输入框与共享标识 | A 消失时 B 不继承 A 的执行；同名同键但表单/语义绑定改变是新目标；稳定重建允许重新核对 |
| 动态价格 | 相同记录的被动价格变化不刷新重试；目的地、所有者、输入选项或模式变化仍生成新样本 |
| 恢复部分失败与未知执行 | 同 URL 下失败也更新位置；不丢未测范围；未知结果不会被新会话、成功截图或另一成功动作清除 |
| 重启接续 | 保留全部历史成功来源、失败条件额度和未测范围；原始发现行与活动对应组分别计数 |

指标应同时输出分母和原因分组，不仅报告一个“恢复成功率”：

- **到达成功率**：`TARGET_REACHED / 合法目标恢复请求`；另列严格检查点成功率、被拒绝前置条件、不可达、未知、无匹配。可恢复的确定性 fixture 要求 100%，预置失败不得出现一次虚假成功。
- **恢复耗时**：每次恢复 wall time 的中位数和 P95，拆开观察/执行/初始化/审阅；真实站点对照目标是 P95 不退化超过 10%，并减少整页重启占比，属于待测门槛。
- **必要重入与无理由重试**：依据未测目标、真实路由、当前重放许可和新增子覆盖判定。fixture 无理由重试必须为 0；必要重入不能计成新动作覆盖。
- **新增覆盖**：当前实际 attempt 数、首次验证的操作样本数、历史复用数、到达未执行数分别列出；A/B 两个确定分支都必须出现独立成功证明。
- **待测范围增长**：原始行、对应组、活动/等待/不可达组分别计数。100 次纯价格刷新不得增加模式样本或重试额度；不存在的旧目标保持等待，不因消失记完成。
- **JEV/LLM 调用**：逐类计数并列耗时、上下文大小、原因；确定性恢复、身份对应和覆盖核对不应调用模型。本地确定性场景要求 0 次决策模型调用。

本阶段测试是上述契约的回归，不是对真实网站的覆盖率声明。尚需补充真实站点多轮性能、长时间历史增长、浏览器进程被杀后的完整冷启动，以及非局部 JavaScript 模式依赖的故障注入。

## 推翻条件

若受控场景出现跨绑定/跨模式错误继承、未知执行被清除、失败后丢失待测目标，应先停止推广并修复契约；这些不是可接受的性能权衡。若可恢复场景仍大量依赖严格中间状态或总是回到起点，且目标恢复/持久化失败额度不能明显降低恢复成本，就应把插件调度进一步改为显式图优先与路径代价调度。若现有观察模型不能表达关键状态和目标语义，即使更换调度也无法纠正，则需要重构适配器抽象；仅此时考虑引入更完整的页面分块实现。
