# 统一上游待办与验证后续测验收

日期：2026-10-16。基线 `9fd8103`，分支 `codex/upstream-interventions`；使用独立工作树，不修改其他任务的主工作目录。

本轮用户选择先实现两项：把各类待处理原因汇总给上游，以及上游决定/人工修复后验证并继续。真实 OKX 扩围和更多交互适配暂缓，本轮没有新真实站点覆盖结论。

## 实现与验证范围

1. `interventionMaterial` 汇总观察、区域、控件、深度、身份、退出、恢复、环境、发现和预算原因；同一恢复结果影响的操作合并，给出依赖、记录引用和原协议入口。暂缓、不测与历史结果保留，材料消失不计成功。
2. `respondToIntervention` 在统一命令队列内检查当前条件和目标，再调用原领域接口；慢速答复过期拒绝、不改绑，重复请求不重放，进程重启记录中断。
3. `continueExploration` 重新观察并校验，保留未决工作及原预算，允许独立已批准样本继续。页面可验证的原退出契约由程序核对；业务恢复和未知结果需要调用方验证器及明确 UI 预期。
4. SDK/HTTP、持久事件、调用方有界审阅示例、调试页“上游待办”和继续验证结果均已接入。协议见 [INTERVENTIONS.md](../../INTERVENTIONS.md)。

新增用例覆盖：过期答复与错误目标、并发及重试幂等、领域现场验证、范围跳过和差异、共享恢复根因、HTTP 完整流程、异步外部审阅、人工输入修复、已审阅退出契约复核、业务验证器失败/未知/超时/迟到/现场变化、SQLite 重启中的未知提交与中断答复、另一活动会话和消耗预算。含实际表单 POST 计数，证明恢复与重试未重复提交；旧 unknown 记录未改写为 succeeded。

## 结论边界

此功能提供可审计的上游交接与续测入口，不证明任意页面发现完整。`applied` 不是动作效果成功，`started` 不是遍历完成，清除待办不是历史覆盖。自动服务器重置、环境隔离、任意恢复路径、更多交互适配及新的 OKX 扩围继续开放。
