# UI 检查消费者盲测

日期：2026-10-15（Asia/Shanghai）。被测实现：`bbac7d0`。实验分支：`codex/ui-inspection-experiment`。

结论：在一次包含三个合成样本的盲测中，独立子代理发现了一个浮层越界问题，两个正常样本没有误报；12 组引用的字段值均与原始 HTTP 响应一致。它没有查询动作前基线，因此没有完整验证“这次打开是否新增了页面滚动范围”。本次支持“当前结构化数据足以发现这个布局问题”，不支持“弱模型能可靠检查任意 UI/UX”。

## 要验证什么

将项目自己的规则检查与外部消费者的独立判断分开：真实浏览器运行页面、执行打开动作并产生 `inspection.ready` 后，上层能否从通知找到主范围，自行查询历史证据，作出有证据的判断。

测试页是人为构造的已知缺陷及对照，不是偶然发现的项目缺陷。浮层用 `role=dialog` 实现，覆盖用户描述的长 popover 布局机制；本次没有覆盖原生 Popover API 的所有行为。

统一的产品要求是：浮层保持在可见视口内，内容和控件可到达。该要求明确提供给检查者；不能仅凭存在滚动条就推断产品设计有错误。

## 盲测方式

- 工具支持的 5.6 子代理只有 `gpt-5.6-sol`，指定其最低推理档 `low`；这不等于验证了整个 5.6 系列最小模型。使用 `fork_turns=none`，不继承讨论、实现和答案。
- 测试前保存 [预登记](preregistration.json)，随机排列三个样本并使用不含答案的 ID。没有向子代理透露缺陷数量、缺陷原因或正常样本构造。
- 只提供 [检查说明](consumer-instructions.md)、[通知清单](manifest.json) 和只读历史 HTTP 接口。浏览器已经关闭；子代理不获准读取源码、原页面、截图、oracle 或其他目录。
- 代理自主查询 inspection、capture 和弹层节点。HTTP 代理只允许指定会话的检查、当前/入口基线 capture、节点与上下文查询；capture 响应省略重复的完整 details，节点事实经查询获取。没有加入预计算的检查结论。
- 一次调用，不追问、不提示补查、不按答案重试。[原始报告](agent-report.json) 保持不变。

这里是指令约束下的盲测，共享文件系统没有形成安全隔离。HTTP 请求可审计，不声称请求日志能证明所有文件访问行为。实验也没有验证通知订阅重连、续租和消费完成握手。

## 结果与证据

视口均为 800 × 600 CSS 像素。表中前后页面高度来自实验程序保存的 oracle，不是子代理的前后比较结论。

| 样本 | 预设及实际浏览器验证 | 子代理判断 | 关键事实 |
| --- | --- | --- | --- |
| `sample-4598e8c4` | 缺少内容高度约束及内部滚动，fail | fail | 面板 y=80、高 814、底部 894；Close 按钮 y=846..881；内容 overflow-y=visible、max-height=none |
| `sample-851269c2` | 正常内部滚动，pass | pass | 面板底部 438；内部 clientHeight=264、scrollHeight=720、overflow-y=auto；页面高度 600 → 600 |
| `sample-00953b16` | 正常内部滚动，背景本来就很长，pass | pass | 面板底部 438；内部滚动位于后代节点；页面高度 1867 → 1867 |

问题样本页面 scrollHeight 实际从 600 增至 894，新增 294px 纵向滚动范围。记录的是滚动几何，不是对操作系统滚动条可见像素的断言。子代理正确指出面板超出视口，并保留“滚动页面后可能仍可访问下方内容”的限定，没有宣称 Close 永久不可用。

正常样本的面板外壳本身没有 max-height 或内部滚动；实际滚动容器是其后代。子代理识别到了这一点，没有把“面板根没有 max-height”直接当作缺陷。正常样本的 pass 限于记录的几何、滚动配置和命中采样，不等于已实际执行滚动、点击或验证所有输入方式。

按预登记标准评价：

| 标准 | 结果 |
| --- | --- |
| 发现不受约束浮层超出视口 | 达成 |
| 引用尺寸、页面前后变化和内部滚动证据 | 部分达成：尺寸与内部滚动有证据；未查询前态 |
| 不误报由后代承担滚动的正常浮层 | 达成 |
| 不把页面原有滚动报告成浮层新缺陷 | 未误报，但未展示基线比较推理 |

代理发送 16 次 GET，全部 200，获得 10 种不同响应，共 463,451 字节未压缩 JSON；存在六次重复查询。没有查询入口基线。逐项核对三份判定与 12 组字段证据均一致，见 [核对统计](evaluation.json)。这些是传输字节，不是模型 token 用量，也不作为成本或稳定性基准。

## 对接入设计的影响

通知中的主范围、历史节点查询、视口、实际页面滚动容器、内部滚动尺寸和约束样式在本例中已经可用。无需为此场景先实现逐节点 UI diff 或中间态录制。

需要在上层检查规则中明确“检查浮层本身”和“检查打开动作对页面的影响”。如果后一项是必检项，应该显式要求读取可比较基线，并让结果报告覆盖状态及未检查原因。提供查询能力并不能保证模型主动使用每一项能力。本次缺少前后比较不是接口无法提供该数据。

后续值得增加独立场景和重复盲测：横向溢出、裁剪/遮挡、关闭后残留页面变化、证据缺失，以及预期允许溢出的正常设计。颜色与文字需要各自的标准和证据；闪烁、白屏等过程检查仍按原规划单独实施。一次三样本结果不能估计真实场景准确率，也不能替代确定性规则测试。

## 复现

在此分支安装项目依赖和 Playwright Chromium，使用仓库要求的 Node 24，运行：

```sh
pnpm experiment:inspection .data/inspection-trial-new
```

选择空输出目录。脚本会启动测试页面、执行动作、断言实际布局与预设一致、保存通知和证据，然后输出一个有效期约 20 分钟的只读 API 地址；Ctrl-C 可提前停止。私有 oracle 与截图仅供实验者核验。脚本本身不调用模型，也没有给引擎加入模型依赖。

另起空白上下文的同配置子代理，把 [实际任务提示](agent-prompt.txt) 中三个绝对路径改为新输出目录，不提供本报告。完成后先冻结首份结果，再与 private/oracle.json 对照；不得把补充提示后的结果冒充首轮结果。

运行原始文件保存在 `.data/ui-inspection-blind-20261015`，未提交到 Git。此目录归档了首轮的通知、说明、任务提示、预登记、oracle、原始报告、请求日志与 HTTP 响应。[requests.jsonl](requests.jsonl) 的 sha256 映射到 [http-responses.json](http-responses.json) 中的原始响应字符串；后者按 hash 去重，UTF-8 编码后可复核 hash。归档中地址已是历史运行地址，不保证仍可连接。

验证：真实浏览器的三个布局断言通过；子代理报告证据与响应核对通过；包含实验脚本的项目 typecheck 通过。
