# Bounded observation authority — design checkpoint, not yet implemented

The metadata-only diagnostic falsified the previous admission hypothesis. Actual own React event metadata and a controlled hidden panel did not make the real model predict a useful interface effect. Requiring that prediction before observing the result is not a sound exploration prerequisite. The subsequent coordinated method correction prioritizes a program loop over adding another model approval.

Four separate facts must remain separate:

1. Caller authorization identifies the current public navigation scope and bounded operation kinds.
2. Program checks identify a current unique candidate, its own operation evidence, scope, exclusions, visibility, obstructions and necessary dependencies.
3. Effect predictions may remain unknown. A permitted attempt must not fabricate an interface-only classification, replay grant, business safety judgment or a guaranteed useful outcome.
4. Actual dispatch and after-observation record success, no change, failure or unknown outcome. Original source obligations and the strict reentry auditor determine coverage separately.

The existing SDK external probe always has risk=unknown and replayable=false. The current OKX wrapper rejects every non-interface risk before native dispatch. Therefore merely changing the plugin's model gate cannot establish a real allowed probe chain. Any implementation must represent explicit bounded observation authority across plugin and SDK, retain unassessed effect metadata, and make the wrapper verify this narrow authority together with its unchanged forbidden operations and route restrictions. Do not forge risk=interface or enable unrestricted observed-ui clicks.

Proposed program domain: current in-scope native public GET navigation to an authorized observed href; bounded hover/focus of a current navigation target with own captured operation evidence; mechanically supported local boundary exits under their existing checks. Program checks do not authorize submissions, editable business controls, arbitrary script execution or ambiguous targets. A contract must opt in to this domain. Every action still consumes the original budget. All other work retains model fallback or unresolved duties.

The next implementation should reuse the existing SDK dispatch, capture, graph, pending-child and arrival mechanisms. The model becomes fallback for a specific unresolved candidate/effect/target/recovery problem after independent program work has had a turn. Disabled models must not prevent program-admissible work. Tests must cover positive delegated/native menus and navigation, negative business/unauthorized/stale/dependent targets, no-change attempts, and fallback isolation. A fake affirmative provider is not positive evidence for this path.

No feature in this proposal is enabled yet. The quota correction is independent and changes scheduling/persistence only. The original 240s/80-action OKX strict-chain gate and independent frozen confirmation remain unproved.
