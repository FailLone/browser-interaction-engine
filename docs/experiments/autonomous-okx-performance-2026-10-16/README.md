# OKX 自主探索：恢复实测与本地开销修复

目标仍是探索 `https://www.okx.com/convert/btc-to-usd` 的完整当前页面交互范围，包含后续出现的菜单和弹层。本记录不是穷尽验收通过。任务 `257f9b5f-79bf-4954-b8cc-11d1a379645d` 沿用原始全页计划、历史证据及累计预算，没有创建一个更小的任务替代它。

## 已确认的开销与修复

1. **观察期间重复重建待办。** 真实重载发生了 34 条分组失效，SDK 原先逐事件重建整份 intervention 材料。现在一次 capture 中的失效、操作完成和审阅 hook 合并到 capture 结束后同步，嵌套 capture 也合并；异常退出会释放合并状态并同步已提交的事实。原始事件全部保留，公开查询仍即时计算，执行校验不依赖通知时机。回归覆盖 12 组同时失效、观察成功及失败，重建均为 1 次，原批准全部失效。
2. **读取证据时扫描永久历史。** 真实库已有 1353 份保留清单，均没有 TTL。8 秒 CPU 采样中，4619 个采样点中的 1311 个包含过期检查调用。现在只索引具有 TTL 或有限期固定记录的清单 ID；单份证据读取仅核对所属清单。索引启动时重建，每次清单写入更新；清单内容、当前观察、开放范围和固定保护仍实时读取，不缓存授权。测试覆盖永久历史不被反复扫描、重启、重启后新增有限期固定、固定到期及实际证据删除。
3. **控件分类历史逐控件重复读取。** 构建一份控件用途材料时，统一读取一次分类历史并按当前观察计算非交互目标；候选过滤和批量分类也共享本次调用的记录。没有跨观察缓存。30 个控件的回归验证只读取一次，撤销一个分类后立即重新待审阅，再改变另一个目标后待审阅增加到两个。

上述变更位于 SDK 和证据生命周期层。插件继续负责 JEV/LLM、任务范围、探索顺序和预算，没有站点专用规则。

加载优化后再次采样 8 秒，5936 个采样点中仅 1 个包含证据过期检查。两次采样覆盖的具体工作不同，不能直接换算总吞吐提升；它确认了永久证据扫描不再占据主要采样。

后续审查继续消除了审阅账本对完整覆盖审计的依赖：`controlInterpretationSnapshot` 只构建当前解释材料，可执行性查询对分类、区域及分组校验材料每次共享一次。旧观察的三次只读测量中，轻量解释约 152–166 ms，完整快照约 2207–2586 ms；这是同一观察下不同接口的开销比较，不能换算真实遍历总速度。没有跨观察或审阅变更的许可缓存。

负面用途缓存不再把点击点、命中目标和 `off-viewport-hit-target` 当作新的用途证据。真实历史材料中的 10 对纯滚动变化可复用负面结果，Previous 禁用变为启用则失效。身份、上下文、结构、真实可达性、遮挡及其他未知事实仍参与失效；执行前始终重新校验。

调试页面原先每次轮询重读约 123 MB 决策和 39 MB 事件。现按事件增量更新决策状态、分页保留历史，任务列表读取摘要，未变化任务不重复传输。部署后原任务处于暂停时，实测更新正文 140 字节、全部任务摘要 3092 字节；首次选择仍加载完整历史一次，任务内容变化时仍返回完整任务。这是传输量测量，不等同于遍历耗时比例。
