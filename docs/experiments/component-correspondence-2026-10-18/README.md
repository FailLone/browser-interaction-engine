# Pair-local component correspondence

Development from `82ba9c7f6e725656fd5b1133f19a5fdf5af0d5f6`, isolated branch `codex/component-correspondence`. The original checkout and old development evidence are read-only. `RESULTS.md` records passed and failed gates; `CHECKPOINT.md` preserves the intermediate experiments. The real-site objective is not satisfied by local model execution alone.

## Contract and provenance

`adapter-playwright/src/component-correspondence.ts` compares complete host fragments, unique captured targets, declared business context, destinations/attributes, supported operations and related mode states. Exact complete pairs are program answers. A complete changed pair may become a question; explicit conflicts, incomplete material, duplicates and unsupported authority do not. It retains opaque record IDs and uses the pre-existing conditional ID/IDREF binding. New descendants remain new work. A change of mode or record is not equivalent merely because the template is the same.

The approach borrows local tree/relative coordinate reasoning from Crawljax/FRAGGEN at `a9e14583e85569f6a7775fa6391c13cf53b3fd6d` (research source map: Fragment.java385/517, ElementResolver.java47/105). No upstream implementation was copied. It does not adopt first-match OR selectors, explored-status propagation, transitive component identity, full VIPS segmentation or histogram equality. No screenshots or image models are used here. Existing upstream license files are unchanged.

Core is model-independent. External records are direct source/current pairs with material hashes and operation conditions. They grant neither dispatch nor completion. The plugin's new `component-correspondence` gap asks one native JEV noul proposition. Probability remains a number with provisional yes/no/undecided bands0.9/0.1. Only an actionable undecided answer may use one LLM clarification. It has256output tokens and disables optional reasoning for this bounded answer. Failures never automatically retry or escalate. Earlier paid truncation is retained as a failed test and is not retried for that material pair.

At dispatch, current SDK availability and correspondence are checked again. A selected original duty may retain its pre-dispatch source binding alongside the actual receipt. Only that explicitly bound original can complete after condition verification and a fresh historical SDK query naming the exact executed receipt. A model answer alone, a sibling receipt, added descendants or a transitive A-B-C relation cannot settle it. Ordinary SDK operation coverage is unchanged.

## Storage and limits

Shared material objects hold complete bounded component JSON. Schema7 adds `componentQuestions`; full audit export/import and compaction preserve question material, answers, reserved calls and negative/undecided results. Identity keys include question/material policy, configured model identifiers, full pair material, business condition and bands. Returned model versions remain in decision telemetry. An unannounced upstream alias change cannot be detected from the alias alone.

The optional channel has4JEV/1LLM/12seconds per240seconds,8JEV/2LLM per task lifetime, and remains subject to the existing total task budget. Input must fit whole; truncation never creates a match. Identical concurrent questions share one request. A crash reservation consumes its count and wait allowance. Exhaustion leaves ordinary program actions eligible.

All paid validation processes use `paid-budget.mjs` and the same absolute `COMPONENT_PAID_LEDGER` path. It reserves before HTTP, charges all failures and batches by judgment count, and refuses beyond8JEV/2LLM. Validation runs are serial. Never delete or reset that ledger. The provider adapter uses one fetch with redirects rejected and no automatic client retry; server-internal routing is not independently observed. configured and actual model names, input/output tokens, HTTP count, judgments, bytes, elapsed time and provider-reported cost are retained. No independent price calculation is claimed.

`replay-local-provider.mjs` is explicitly offline: it returns the actual five recorded responses from the prior successful `local-effects-local-1` run. It checks the question and captured control semantics, maps only the local URL in responses, persists its cursor across process restart and has no provider-network fallback. The original local browser harness and independent auditor remain unchanged. This preserves a full browser regression without spending another two LLM requests after the already-recorded clarification failure. It is not a fresh model-accuracy evaluation.
