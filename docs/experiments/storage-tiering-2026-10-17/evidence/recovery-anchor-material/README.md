## 性能检查点：基线进程超时，对照未完成

`runner.py` / `worker.ts` 固定一次 A→B，使用第十二窗已关闭的最终任务与当前位置。只在内存将 task.status 从 paused 置为 running；不改变预算、使用量、计划、位置或失败债。它不是原来长扫描发生前的精确重放，也不使用 168.994 秒事件间隔作性能基线。

真实 SDK 运行于唯一临时 engine DB 副本，A/B 串行并在两次之间从冻结源重置；源库只作文件哈希及复制，不连接或迁移。实际选择器可让出执行权；有候选时还要调用其最终 revalidate。完整选择数据、回调结果、任务、顺序事件、旧债逐字段比较。只排除不可序列化的私有回调本身，由独立实际调用结果表示；不删语义字段。

资源采样发生于选择与回调结束、输出序列化之前。record accessor 调用数不是物理 I/O，单首对受进程顺序、操作系统缓存和同机负载影响，不支持统计稳定性结论。结果若不等、新 API 未触发、读取次数未减少或耗时明显退化，记录负面检查点并停止，不自动追加样本。

首次启动在归档阶段因旧工具拒绝已提交的文档符号链接而失败，worker 和数据库副本均未创建。原失败、旧脚本和原因分别保存在 `preparation-failure.json`、`runner-preparation-failed.py`、`preparation-failure-context.json`。修正只限于归档运行源码和配置，不改变产品或冻结输入；这是准备失败后的有理由修复，不是新增性能样本。

修复后唯一预定首对只启动了基线：进程在 240 秒上限仍未完成，收到 SIGTERM 后已退出（exit −15）。候选未启动，完整输出比较、读取次数和耗时比均未产生。没有延长上限、修改预算或追加样本。工具没有中途阶段计时，不能把整个 worker 的超时定位为纯 selector 耗时，也不能把它解释为候选补丁的退化或收益。

`execution.json` 保存原结果，`setup.json` 引用唯一保存的源码清单；未产生重复的语义材料。冻结输入、两版源码、两版 worker 哈希均不变；没有活跃 worker，唯一临时目录已删除。本轮性能检查点是 **未完成**，行为检查点仍为 **通过**，两者不混记。
