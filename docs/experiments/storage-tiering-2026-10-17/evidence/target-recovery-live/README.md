## 已证实的行为

修复前的第一轮 3 个反例全部失败（4.33 秒）。隐藏控件使恢复在初始验证就退出；双开关在恢复第一个开关并改变价格后被整页比较拒绝；真实浏览器重启后也被隐藏材料阻断。

以下是 `09-live-integration.log` 同一轮的单次测量。每个正例在到达后通过 SDK 填入此前未执行的 Amount；独立 DOM 核验值和一次 input 事件，SDK 收据的 `conditionVerified=true`。到达结果本身仍为 `currentExecution=false`、`coverageGranted=false`、`checkpointVerified=false`。

| 场景 | 恢复操作 | 恢复耗时 | 新输入耗时 | 入口重开 | 新输入证据 |
| --- | --- | ---: | ---: | ---: | ---: |
| 隐藏两层菜单，价格不变 | Outer → Inner | 560 ms | 184 ms | 0 | 1 |
| 隐藏两层菜单，价格变化 | Outer → Inner | 562 ms | 174 ms | 0 | 1 |
| 两个模式逐步恢复，价格随每步变化 | Mode → Option | 548 ms | 173 ms | 0 | 1 |
| 关闭浏览器/SDK后，用原 session 和历史证据恢复 | 新 driver 的入口捕获 → Outer → Inner | 907 ms | 175 ms | 除新 driver 初始化外 0 | 1 |
| 模式变化使当前源无法接续、必须重开入口 | Reopen session entry → Outer → Inner | 929 ms | 191 ms | 1 | 1 |

源模式不同在恢复前明确为 `sourceEquivalent=different`；只有恢复到原模式并实时核验后才到达。最后一例说明没有为了避免重载而删除全局重放。重启接续保留原 SDK session，非拿新 session 偷换历史 checkpoint 所有权。

负向验收分别证明：

- USD 审阅目标删除、Amount 被意外修改、仅标 `aria-readonly` 的输入被修改：第一步后停止，不执行第二个逆操作。
- 严格 checkpoint 遇到价格不同仍失败；新后置条件没有改写旧 canonical。
- 已选后缀的 Inner 实际无效果：`UNREACHABLE/target_not_reached`，保留失败，0 次额外入口重开，0 个新输入。
- unknown 收据写入本测试临时库后再次重启：1 次阻断查询，0 次浏览器附着/执行，旧 unknown 原样保留。这里是显式崩溃账本故障注入。
- 途中目标 preflight 首次返回未知、若重试则返回 valid：仅调用一次并返回 `UNVERIFIED`。这是显式接口故障注入，见 `10-stop-is-sticky.log`；不能以第二次碰巧成功覆盖未知结果。

## 契约与成本边界

core 只解释版本化后置条件的通过/失败/未知；原生只读、模式、控件结构由适配器解释。每一步的预期是“当前事实只修改本次声明字段”，不是直接复制最终 checkpoint。投影保留全部捕获控件、可编辑值、非局部选择器、边界及绑定，只允许有明确原生 `readOnly` 属性证据的非交互输出值变化。缺证不能拿 ARIA 声明替代；旧观察缺少新字段时不享受这项放宽。该证明不涉及隐藏 JavaScript 状态或业务状态等价。

后缀选路最多查看本 checkpoint 的 16 条路径记录、做 4 次首步源条件核验；同时约束剩余动作预算。它不扫描所有历史状态，不更改严格状态图键，不合并覆盖，不把跳过的前缀记作已执行。每一步仍通过原 `repetitionAssessment` 和 dispatch guard；选中路径失败/未知后直接返回。达到扫描上限不意味着待测范围不存在。

可确认的成本收益是少一次入口重开：动态菜单对照从 3 次恢复操作降为 2 次，浏览器重启后也不再重复重开刚初始化的入口。06/07 对照的恢复时间为 929/571 ms，但这是一次小页面样本，不能推广为吞吐量提升比例。局部后置条件有额外的当前观察线性投影成本；本轮没有测大页面 CPU、任务库存储大小或长期前沿增长，不能宣称这几项改善。没有增加另存整页的恢复快照；临时测试数据库和浏览器均已关闭清理。所有用例无 JEV/LLM。
