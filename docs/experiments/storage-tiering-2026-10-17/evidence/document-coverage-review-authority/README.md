# Receipt coverage review authority

The new `ControlReviews.coverageAuthority` revalidates the authority attached to a successful interface receipt. Native supported operations without review references retain their source and target objects. Reviewed operations require the actual referenced review, exact retained source conditions, unique instance, three-way review attributes, verifiable ordering, and the explicit reuse ancestry. A revoked/superseded/missing/forged/cyclic source rejects coverage authority on the next query. A terminal review invalidated by this receipt's own after observation remains historical evidence. Reuse ancestors may be invalidated by document changes, but must retain their original source and opted-in reuse conditions; this does not reactivate them.

An earlier tentative/unknown target may receive an ephemeral projection through the unchanged `coverageProjection`. A supported/interface target still requires complete review provenance. No helper call writes records, rewrites observations, resolves identities, or authorizes dispatch. The caller must separately establish actual receipt ownership, document/dependency/context/operation equality, all selectors/inputs, and unresolved-outcome gates.

Validation: one targeted invocation, 101/101 passing (50 new in-memory authority cases + 51 existing receipt correspondence cases). Exact command, source hashes and exit status are in `validation.json`; original output is `tests.log`. No performance conclusion. Consumer integration and aggregate typechecking belong to the root task. Existing owner-change and large historical evidence are referenced in the surrounding experiment; they were not copied or rerun.
