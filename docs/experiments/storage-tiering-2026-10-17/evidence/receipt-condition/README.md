# 实际执行与条件结案分开

本补丁只验证一个结论：同一个 before/action/value 的成功记录，不足以单独结清该 before 下的待测条件。基线工作区为 `codex/exploration-layered-refactor`，HEAD `3cd2ac5c1f59b840950270af8434f38632813c47`；这次修复接在已完成的派发来源证明之后，没有改变恢复、到达或重放许可。

独立本地浏览器反例中，保留观察仍是 A，派发前隐藏父记录已经变 B，原生 checkbox 的处理函数实际读取 B。旧插件直接结案把 A 记为成功；修后保留实际成功和尝试消耗，把 A 留为未完成。稳定来源的真实正例仍可结案。两种结果分别验证，不能把拒绝所有结案当作修复。

SDK 新增同步只读 `operationReceiptCondition`，返回实际成功事实及策略限定的条件证明。查询使用真实输入，重新读取未知结果、恢复债、身份与审阅撤回。插件的直接结果、同来源成员核对、审计免缺口三处都消费它。启动与最终结案前重核旧完成项；缺证的旧 completed 任务退为 blocked，保留来源、尝试、tried 和路线债，不创建新会话证明旧成功。等待只作用于该具象义务，用户排除和其他新来源继续按原范围处理。

验证记录按检查点保存，不能合称一次固定版本全套通过：

- [SDK 记录](sdk-validation.md)：新查询、原文档覆盖及已知条件不同的拒绝；保留并行接入期间的变量遮蔽失败和单项修后复验。
- [插件记录](plugin-validation.md)：实际 A→B 红测、实际稳定正例、三条结案门、旧任务重开与等待语义；保留新协议夹具缺方法的初次失败。
- 根类型检查的初次失败保存在 `typecheck.log`：新测试夹具缺少 ActionCandidate 两个必填字段；最终检查另存，不覆盖失败。
- 独立审阅发现补证来源遗漏：旧 `resolvedBy` 与后来的 `coverageResolvedBy` 共存时，复核也必须纳入相关成功记录，不能把合法补证再次丢失。修复和定向检查记在插件记录。

收尾时，补证保持与非必需项不传播两个检查点通过（2/2，未重跑原 57 项）。第二次类型检查在 `final-typecheck.log` 保留新增夹具给 `exhaustive: false` 类型赋 `true` 的错误；该非必需范围夹具改用产品允许的 `false`，没有改产品逻辑，单项复验 1/1 通过，日志为 `nonrequired-type-fixture.log`。最终根/core 类型检查通过，见 `typecheck-verified.log`。独立只读审阅的两处 P2 均已修复，未发现其他确定阻断；源码、检查点与保护工作区标识见 `validation.json`。这些分开的记录不等于最终版本整套重跑。

portable 继续表示既有适配器抽样策略，document 证明有界的同文档事实；二者都不保证任意 JavaScript 业务状态或浏览器快照还原。旧缺图、缺派发证明的记录不会事后补证。终审撤回和临时任务库重启检查包含显式协议替身，真实 SDK 的拒绝边界另由 SDK 检查验证，不能称为真实 OKX 重启验收。

本次没有运行全套、80 次协议、真实性能基准或真实 OKX 续测；没有操作原测试浏览器、服务及任务数据库。每次同步核对复用同一 receipt 的查询，但不同 receipt 仍可能各自扫描会话账本，M 个 receipt 对 N 条记录存在 O(M×N) 读取成本；新增任务审计字段也有占用，未量测净变化。后续先评估同次查询的批量共享，不延长授权缓存寿命。当前不能宣称恢复成功率、端到端速度或磁盘占用得到改善。
