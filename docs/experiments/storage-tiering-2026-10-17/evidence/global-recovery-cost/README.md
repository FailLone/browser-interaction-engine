# Run18 全局恢复超时：覆盖核验的必要条件索引

本补丁只处理固定 OKX 回放路径中的已定位超时成本；交付标准仍是局部、全局恢复到达后实际继续未测操作。

基线 `ae897380d2248783176769a0bcaebb60fa4fbe8d`。从被中断的 run18 独立引擎库只读备份出临时副本，没有打开任务库或浏览器。原 SQLite 与 WAL 内容哈希不变，见 [ownership.json](ownership.json)。

一次有界离线 profile 定位：`capture finally → interventions.sync → getFrontier → reconcileCoverage` 每次重新派生大量无对应成功记录的操作条件。现场有 187 份观察、3361 条前沿、71 个动作回执；该材料构建用时 14.405 秒。[原始采样汇总](baseline.json)

补丁仅为有完整成功证据的样本建立索引，字段严格来自最终等价键：解析后身份或原文档实例、操作、输入、完整声明上下文、risk。候选不可能匹配任何成功样本时，跳过昂贵 portable 派生；命中时继续原完整核验。retained receipt 回退和两个已知 portable 样本不同的阻断仍独立执行。没有持久缓存，没有改变模式、身份、权限或目标到达校验。

[配对结果](comparison.json)：同一输入，原核验 3365 次 sample，新核验 77 次；直接核验耗时 9.086 秒到 0.262 秒。两侧覆盖对应 Map 逐项一致，输入未改写。**该真实材料两侧 Map 都为空**，因此另有正向、别名、实例、不同输入/上下文/模式及 retained 回退用例，不能以空结果相同单独证明没有漏测。

[完整材料复测](candidate-material.json)：14.405 秒到 5.966 秒，82 个干预项及整个材料摘要完全相同。单次离线 profile/配对结果不是线上恢复性能或成功率；没有为精确倍率反复跑基线。

验证检查点：新增纯测试与 receipt 测试 28 项；现有覆盖、SDK 到达、A/B 和本地浏览器恢复/unknown 路径 58 项；两项类型检查通过。唯一诊断重跑是审计脚本将 187 份大图拼成一个 canonical 字符串超过 JS 长度限制，改为逐记录摘要后继续；首次失败发生在执行核验前，没有修改产品以迁就审计。

下一检查点是 [run19 固定路径协议](../real-okx-19/protocol.json)：同一历史 USD 目标，局部和全局各自到达后，通过有守卫的 SDK 派发金额输入并验证现场值与回执。未通过这个检查点不能称“回放可用”。
