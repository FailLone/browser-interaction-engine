# Task-store hot-write follow-up

Compare exact archives `106a1cd` and `855a3a4` with the same worker bytes. Product changes are limited to lazy canonical item parsing when its stored hash changes and a 64-row cold-packing eligibility probe. Neither schema nor read format changes. Existing `schema4` full-read improvements remain; an attempted batch-JSON parsing feasibility probe was slower and was rejected.

The run7 frozen copy has 803 plan occurrences and one current round. All are plain rows: only 34 plan rows are settled, below the 64-row automatic cold-packing threshold. Current-round JSON is 446,912 bytes; the header is 293,862 bytes before compression. Every named unchanged round previously incurred a redundant JSON.parse, and each below-threshold cold scan transferred 83,288 bytes of completed-plan JSON. The new code retains the same automatic packing trigger, including previously eligible plain rows, and explicit maintenance still packs below the threshold.

`runner.py --prepare` creates a complete private frozen-directory copy, exact source archives with workspace links inside each archive, and two reusable SQLite seed files. The run7 seed must remain byte-identical to frozen plugin/explorer.sqlite even after initialization. The synthetic history seed derives 5,000 plan rows from run7 values (4,990 succeeded, 10 unresolved) and adds one historical round. These intentional synthetic mutations are a cost control, never a live replay or coverage claim. Original decisions/events remain complete in the run7 case.

`runner.py --run` starts 12 independent measurement processes: each fixture receives three baseline/current pairs in AB, BA, AB order. It refuses to overwrite an executed evidence directory. No provider, BrowserEngine, browser, service or live task database is used. Every writable database is a fresh private copy of its seed. Source archives and private/frozen inputs are hashed before and after.

Each process reports initialization; first and repeated full task reads; active-item and header reads; header-only CAS; unchanged-round CAS; active-item CAS; changed-round CAS; compatibility saves with unchanged items; explicit maintenance. Correctness comparisons, digest/byte accounting and output serialization sit outside individual operation clocks. SQLite transaction-body durations are measured separately to expose changed-row JSON.parse moving inside the write lock. Qualification threshold hits add an extra bounded SQL probe and must not be presented as a free optimization.

All initial/final task fields, ordered persistence occurrence handles, original events and decisions are retained in gzip semantic artifacts and compared structurally across versions. Each intermediate full state is also checked against the explicit expected task and ordered handles. Only revision/time, one active row's reason, and current-round action/tried audit values are deliberately changed by the workload; original unknown/recovery/route debt and references are preserved. New random CAS tokens are tested for changes, stale rejection and maintenance stability rather than byte equality between independent processes.

First-read measurements use fresh processes but do not evict OS file caches. Process maxRSS includes task fixtures, full correctness comparisons and semantic audit serialization; report both absolute values and differences without claiming isolated production heap. Report DB, WAL and SHM separately before/after explicit maintenance and after close. No storage saving or full-read improvement is assumed. Preserve unfavorable measurements.

Run only after the root agent releases the serial CPU window. Reproduction requires Node 24.22.0, the checked-out workspace's installed dependencies, Git history and the complete frozen-7 directory. The archive-link helper is the already archived `real-okx-6/audit-serial/runner.py`; its SHA is captured with the new worker/runner SHA. No private DB/material files belong in the repository.
