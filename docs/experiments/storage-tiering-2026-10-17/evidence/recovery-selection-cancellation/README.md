## 实现边界

- `runtime.ts` 的计划、检查点索引、审阅锚点和来源扫描以真正的事件循环让权实现协作式中断。廉价条目累计 128 工作单位，历史来源/锚点权重 16；SDK 候选仍分为至多 8 项的同步批次。短扫描不为每个条目建立异步等待。
- 每个等待边界核对停止、任务版本、预算，以及当前完整观察、动作和可用性。历史来源、动作投影、路线条件和负面候选判断不跨等待复用。同 ID 的宿主观察覆写也不能绕过核对。
- 锚点排序只保留检查点引用与归类，不保留全部历史观察。这里没有单独测量内存收益。
- 跨批次保留的备用候选重新验证；短异步函数的最终返回间隙也受保护。在实际选中恢复候选后、预留/记录恢复尝试前，核对唯一检查点、来源/动作/转换事实、路线条件与旧重试债。严格检查点、目标到达和来源返回保持原来的独立契约。
- 原待测范围、失败债和 unknown 保留；中断或事实失效不能改记无法到达、完成或覆盖。SDK 实际到达与执行验证仍是必要条件。

单个同步 SDK 查询、历史列表读取和投影计算仍不可抢占；上述工作单位不是毫秒级响应保证。完整事实复核增加读取与摘要计算成本，后续性能优化需单独证明等价和成本，不能沿用本次行为结果。
