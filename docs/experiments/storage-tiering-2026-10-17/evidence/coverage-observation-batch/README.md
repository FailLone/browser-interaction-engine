# 按需覆盖核对：保持完整输出，减少历史物化

本补丁只有一个结论：已知只读组合的前沿核对不再先加载全部历史观察。SQLite 提供一次同步只读快照，核心按需读取并最多强持有四份完整观察；控件索引使用弱引用，retained 回执索引只保留记录引用。没有跨调用的覆盖、身份、到达或执行许可缓存，没有数据库格式迁移。

完整 `coverageMaterial`、audit/report 保留数组全量路径及历史损坏检查。自定义覆盖材料、适配器或不支持快照批读的存储保留原路径；本轮 Memory 不新增批读支持。正常 SQLite 读取同处一个事务快照，query_only 在退出时恢复；错误原样传播，不能把错误变成空待测范围。候选查询不再发现未引用的损坏历史是明确的语义边界，不能将其称为完整历史审计。

## 保存的真实事实对照

冻结 v8 输入哈希不变。两次独立进程各只运行一次相同 getFrontier 查询，各设 30 秒上限，无浏览器、任务库或模型。对照版仅显式关闭新批读能力；新版本默认组合启用。完整 3,073 条前沿输出共 6,574,233 字节，双方 SHA256 均为 `2cacf022a01e3e943e9ae90599e33c41a69878eef53096aba86e84e533df060e`，不是仅比较计数或队列是否为空。

原全量路径加载 176 份观察；新批读请求 108 个不同 ID，共 131 次读取（含 23 次淘汰后重读）。进程峰值 RSS 为 1,579,136 KiB 与 589,408 KiB，查询记录耗时为 5,430.467 ms 与 2,402.020 ms。双方被测查询写入为零。

**性能边界：** 基线运行与根类型检查发生 CPU 竞争，因此耗时仅作为本次观察值，不能计算严格加速比例；RSS 包含构造器。此对照历史的 equivalentItems 均为 0，合法覆盖正例由上述独立测试证明，不能拿空等价集单独证明正确性。本结果不证明真实恢复成功率或端到端耗时改善，不再次重跑基线；下一检查点是一次有明确补丁理由的 240 秒真实插件接续。
