# Receipt-bound dispatch witness

The owned local counterexample confirmed a pre-existing cross-observation coverage defect. A hidden selector's parent changed from record A to B after the retained before observation. Both the old forced-graph preflight and the graph-omitting preflight returned `valid`. The real checkbox command succeeded and its handler read B, while the before observation still contained A. The previous document coverage fallback incorrectly accepted the older A target. `dispatch-gap-before.json` and its failing safety-oracle log preserve this result.

The separate correction adds a one-use `browser-owner-dispatch-v1` witness to the actual after observation. Preflight retains immutable source coordinates and a graph digest. After the existing native target/instance checks, the default driver takes a fresh bounded DOM sample immediately before invoking the native control command. A matching graph, URL, document, browser, declared context and actual action produce a witness. Its full action digest includes a supplied input value. A mismatch, incomplete graph, read failure or custom implementation only withholds coverage evidence; it does not change the execution result. Multi-stage scroll, dismissal and history operations do not produce this witness. DOM context rules and custom context hooks also decline because their separate reads cannot establish one final graph/context sample.

Capture consumes the slot at entry, including ordinary, mismatched and failed capture. It attaches evidence only for the matching before/action and source graph/context. The coverage reader independently verifies these bindings and timestamps. Old receipts without the witness remain actual successes but cannot obtain this document fallback. `browser-document-coverage-v1` keeps its sampled-condition policy name: this is stricter receipt validation, not a migration or backfill. Portable identity, arrival, replay and permissions are unchanged.

The first corrected counterexample passed with the real B command still successful and the old A proof rejected (`dispatch-gap-after.json`). The final targeted checkpoint passed **77/77**: five real local/Memory-clone witness cases plus the 72 existing pure graph cases. It covers stable actual supplied input, missing/changed/borrowed witnesses, ordinary/failed/missing-graph capture consumption, changed owner or declared context in the second `beforeAction` hook, and a review/native basis mismatch that must remain rejected. Pure graph fixtures now explicitly provide a synthetic witness; real integration fixtures obtain one only through native execution.

Root independently reran the existing document-operation coverage, nonmodal reentry, stability and validation tests: **44/44 passed**, with the three product file hashes unchanged (`dispatch-existing-checkpoint.json`). This rerun was needed because the correction adds dispatch sampling and an after-observation field. Final root/core type checks passed with the five implementation/test hashes unchanged (`dispatch-types-checkpoint.json`). The final scope therefore has 121 passing targeted cases across two runs, not a full-suite result. No 80-trial protocol or real OKX run was performed for this correction.

Failed checkpoints remain in place. The initial combined run was 75/76: the attempted checkbox false-to-true positive had different review/native bases, correctly rejected by the existing contract. This became an explicit negative test; the positive uses two consistently reviewed text-input samples and a real supplied value. The next single checkpoint reached the positive proof, then correctly hit immutable-observation storage while testing corrupt evidence; those variants now use independent MemoryStore copies. The corrected single checkpoint passed, followed by the final 77/77 run. No product guard or safety oracle was relaxed to resolve either fixture issue.

This proves refusal of erroneous **historical cross-observation reuse**, not complete condition attribution. The plugin's existing own-before exact-receipt completion semantics and direct execution statistics remain a separate issue. The witness is the last bounded sample before the native command, not an atomic DOM/input transaction, and does not enumerate arbitrary JavaScript dependencies. The after frame may legitimately remove the target or change state. A normal eligible command now performs an additional full DOM read with graph after the existing graph-free preflight; this correctness change has a real cost and is not a net performance claim. Query-side repeated graph hashing is also not optimized here.

All fixtures used their own localhost server, headless browser and in-memory records, with cleanup in `finally`. No real browser, provider, task database or frozen experiment was opened or modified. Exact commands, exit codes, final source hashes and evidence hashes are in `dispatch-validation.json`; earlier evidence was retained once rather than copied.
