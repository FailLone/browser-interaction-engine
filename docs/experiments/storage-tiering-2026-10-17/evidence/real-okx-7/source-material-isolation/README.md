## 实现与边界

`855a3a4` 让 SDK 一次获取同一来源观察和动作，并由插件在一次同步筛选内复用来源条件；保留原 8 来源缓存上限、排序、失败债和派发复验。它的初版仍对已隔离结果再次复制，净耗时仅减少 2.15%、诊断 RSS 增加 6.51%，负面结果完整保存在[初版对照](../source-material/README.md)。

`875ce50` 为 Persistence 增加可选的 `recordReadIsolation: 'detached'` 契约。内置 Memory/SQLite 的每次记录读取均返回独立对象；Retained 只在被绑定的读方法仍与声明匹配时转发此能力。组合 API 只有在读取前后均声明隔离、SDK 公共读取方法也未被覆盖时才省略第二次复制；第三方未声明、声明撤回或覆写的路径继续防御性复制。契约不表示读到最新游标，不提供跨调用事务快照，也不授予覆盖、恢复或重放权限。

读取次数从 1,945→1,313（均含 1 次 session；Observation 为 1,944→1,312）。动作 scoped 查询仍为 656 次，唯一来源 32 个。第一对样本 require 累计时间 24.303→16.845 秒；动作读取 453.618→469.537 毫秒，保留这一小幅负差，不把读取次数下降等同于所有子阶段提速。没有跨筛选持久缓存。

## 完整语义与来源

输入沿用 `fresh-deferrals-preparation.json`：第七窗终态的 803 条计划、真实先前观察、实际先前事件的轮转 cursor；只清空暂不可达原因缓存，不删除来源、计划、失败债或 unknown。它是明确构造的反事实，**不是精确现场前态**。worker 运行固定源码的真实 SDK 继承方法和 SQLite 解码实现，通过实际 SQLite 原型读取隔离声明；没有构造会初始化/迁移数据库的 SDK 或 store。只读副本启用 readonly/query_only，total_changes 保持 0。

输入任务 2,188,693 字节，结果任务 2,234,061 字节，选择结果 3,625,128 字节，事件 118,660 字节，均两版完全相同。全部 270 条 `obligation.route_unavailable` 事件有序相同，完整组合输出 SHA-256 为 `7b468082a0b0ead8fbaa589be08e46e029ad60c466c45bc92dda3e113e7f6dc6`。完整 JSON 按 SHA 无损 gzip 保存，六个输出的映射见 `semantic-artifacts.json`；这只是验收材料去重，不是产品任务库存储收益。

`execution.json` 保留六条原命令、PID、开始/结束时间和 exit 0，以及 source archive、输入、原 worker、各 archive 内 worker、私有副本与冻结数据库的前后哈希检查。`runner.py` 与 `worker.ts` 可复验；setup 中记录确切输入和依赖，需要原冻结材料及两个固定 Git 提交。独立哈希核验见 `artifact-verification.json`。

本次性能对照刻意不包含后续 `e06f057` 的隐藏审阅来源门禁，因为它会改变选择工作量。该修复的行为对照和 80 次原协议单独记录。任务库压缩、完整读取、真实浏览器恢复成功率和真实穷尽均不能从这组数据推出。
