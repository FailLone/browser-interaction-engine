## 两个独立结论

1. **审阅目标不应强制还原整页。** 新 `reachControlReviewTarget` 复用 core 既有恢复路径，在当前检查和每一步退出/重放后做控件唯一对应、活动边界、可审阅材料及实时目标 preflight。默认目的为取得当前新材料；当前材料已有分类、需要追补旧 A 条件时，则要求历史来源条件等价。结果明确携带目的与 `sourceEquivalent`，不授予执行、覆盖或 checkpoint 成功。unknown 执行仍在重连/恢复前阻断，途中未知也不会靠新会话或后续到达洗掉。
2. **文档实例编号不能无条件进入跨文档状态等价。** `0208556` 引入 `observable-v8`，使用既有完整 `region-structure-reuse/v2` 证据核对唯一控件、owner/row/ancestry 指针链和 record/template/slot 后，才生成紧凑结构摘要。缺证、歧义、实例专属身份保留原键。旧版本的 canonical 原样保留；严格状态仍包含动态价格、成员、滚动范围等实际事实。这个补丁不声称任意动态页面可以精确回放。

审阅台账是第一个结论的必要配套：范围匹配只找候选，SDK 对应才证明来源。A、B 可分别累计小型 proof 引用；所有来源完成才结案。撤销 A 只撤 A，scope 变化重新验证旧引用，unknown 不结案。分类因后续场景变化而 invalidated 仍可能是有效历史证据；revoked、缺失或不唯一则不行。暂停、停止、恢复失败时只撤回无效完成，不通过新的当前分类补写成功。

成本检查验证算法行为，不把测试进程耗时当作网页性能收益：

- retained classification 按来源分组，组内分类记录和唯一匹配各一次；不同分类共享 reuseFrom 祖先的重复读仍存在，未伪称全部消除。
- 当前审阅材料的页面模式/成员索引在一次 reader 中构建一次，各目标投影缓存仅在该 reader 内有效；真实模式变化使等待键失效，被动价格变化不会单独放开重试。
- 批量对应接口目前共享记录读取，尚未共享所有不同控件对的模式/分类投影；多个唯一目标仍有按对重复计算的成本。不能把“每图只读取一次”写成“每项事实只计算一次”。
- proof 仅存引用，结构键仅存摘要，不重复存完整路径；没有测本次任务库或总磁盘的净收益。新增可审计来源引用本身也有成本。

## 未关闭的真实验收

本轮没有取得新的真实恢复成功率、恢复耗时、恢复后新覆盖或存储比。第十四窗仍是失败记录，不能被离线测试覆盖。

当旧来源的非局部条件不可验证时，即便当前材料可读，也只能增加当前证据，不能补签旧来源成功。要求旧来源等价的恢复会明确停止；本轮没有消除这一可观测性边界，也没有扩大框架到任意 JS 内存快照还原。

下一次独立的同预算窗口只检查这一条链：关闭必要弹层 → 实时目标到达 → 当前材料审阅 → 保留未等价旧来源 → 继续产出覆盖。分别记录退出、图路径、入口重放次数及耗时，当前材料到达与历史条件到达的数量，必要重入/无理由重试、A/B 剩余来源、unknown 阻断和模型调用量。发现未验证到达立即停止该轮，不靠延长预算补成功。

若真实页面仍在当前目标已满足时重开入口，或 B 已完成时仍反复停在 B 而无法调度 A，或旧 unknown 被解除，或动态真实分支因结构摘要被合并漏测，则本轮相应结论被推翻；应使用本轮同一输入/阶段证据定位，不宣称任务库优化或队列清空能代替这些验证。
