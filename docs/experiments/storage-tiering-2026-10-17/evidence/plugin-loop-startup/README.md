# 不可能产生调度别名的归一化提前结束

本补丁只支持一个结论：已确认 v3 调度键与原 v2 键相同后，不再为一个不可能产生别名的项目读取其余历史来源。保留原始待测项、条件键、unknown 债务、覆盖和执行门禁；不扩大缓存，不新增持久审计。

原实现逐项处理来源，只保存 8 份来源索引。没有新增审计的项目下次仍需从头读取。`host.actions` 为验证来源归属，还会再次读取同一整观察。一次 30 秒硬上限的离线诊断直接调用 `normalizeOperationScheduling`，未启动 engine/plugin/browser，也未打开任务库。

基线保留在本目录，候选见 `../plugin-loop-startup-candidate/`。两个诊断脚本逐字节相同；原 engine/WAL/SHM 与任务输入哈希不变。候选 `changes=[]`，完整任务前后 SHA 相同，数据库 total_changes 为零。基线未完整执行，因此不宣称全量基线输出对照；也不把函数级改善换算成整体启动或恢复提速。

## 正确性边界

提前结束位于全部现有来源、操作、原键和多来源一致性检查之后，并先执行原来的 `toKey=key` 赋值。此时若键等于原键，后续一致只能仍然相等，后续不一致、缺失或 unknown 也只能拒绝；两种结果都不产生别名。已有失效审计仍由原有出口删除；有效旧审计追加来源的冲突仍先被现有门禁拒绝。没有缓存永久 no-op。

独立只读审查确认，在现有一次同步、捕获事实不变的契约下，计划、变更与别名输出等价。调用次数及缓存预热本来就会变化；不声称带副作用的自定义 host 或畸形后续对象的异常行为完全一致。

新增六个用例检查相等键后续一致/缺失/unknown/歧义/变化和失效旧审计删除。连同原 factory、调度键与 runtime 用例，51/51 通过，root 类型检查通过。仅重测改动涉及的三份测试，不重复身份、恢复或存储全套。

下一真实验收仍沿用 240 秒上限。其唯一重跑理由是此处已有实际成本定位、窄补丁及针对性验证；如果未到达目标恢复，不延长预算或将当前操作成功替代闭环。
