## 先修观察稳定性

根因有两个。局部就绪窗口曾使用快照处理结束后的墙上时间，一次较慢的快照处理可能被误算成多次稳定采样。其次，页面上任意原生输入框就绪就可能结束观察，即使刚执行的弹层入口仍未稳定。后置校验随后把入口结果判为 unknown，恢复因此中断。

core 现在给 driver 提供可选的已执行操作和原观察上下文。适配器的全局、交互、局部窗口共同使用每次真实 DOM 读取结束的采样时间。普通观察仍能报告局部就绪；操作后观察只在该操作自己的原生作用域就绪，或全局相关交互稳定时提前结束。继续采样受原超时预算约束，不重发操作，不把持续不稳定、真正读取超时或 unknown 改成成功。

同文件独立因果对照：5 项中旧版 3 通过、2 失败，重复红测为同样两项失败；修复后 5/5。两个反例分别在真实执行后注入快照处理延迟，及短暂改变独立控件的文字。没有修改时钟、就绪标记或执行结果。持续变化的负例仍保留 unknown，并阻止下一次输入；被动报价变化和已就绪原生字段的局部执行仍可通过。

冻结修复版相关回归 8 个文件、84/84；类型检查通过。原恢复协议双方各 30 次：静态嵌套、报价变化嵌套、弹层重入、已就绪动态报价目标各 5/5 实际到达并通过 SDK 输入；局部逆操作失败和 unknown 各 5/5 正确拒绝，错误到达声明均为 0。**普通对照的旧版也全部通过**，它未复现上一轮偶发问题；本轮因果收益来自独立受控红测，不能写成真实弹层成功率从 0% 提升到 100%。

## 调度契约

持久化计划保留未完成目标、来源条件和原始证据。新的调度记录仅保存目标轮换位置、局部批次数、路线与旧重试额度的关联及不可达原因，不保存执行许可或覆盖结论。当前观察投影在每次同步选择时重建；历史别名不能变成永久完成证明。

当前可执行工作获得有界优先权，连续最多 4 项后给远端未测目标调度机会。无可用远端路线时继续处理当前工作。失败消耗对应条件下的恢复额度并轮换目标；新的目标记录 ID、报价变化和重启不能刷新旧额度。新路线以 SDK 核验的保留源条件区分目标：同控件 A 的失败不能消费 B 的第一次到达机会。旧路线没有条件字段时不猜测补齐，继续保守共用原失败额度。旧复合路线能够对应时沿用原额度，不能对应时保留明确缺口。

同一 SDK 会话可根据保留来源和检查点建立到达请求，栈为空也不丢失待测目标。新会话使用已有 EntryRoute 和逐步重复许可，不把另一会话的检查点搬来直接恢复。隐藏候选不等于目标到达；当前已经可见但受执行限制的控件也不能靠恢复获得许可。授权范围删除后，历史帧和派生待测项不能继续授权返回。

## 实现入口与能力边界

- core/适配器：`CaptureContext.afterAction` → `capture` → 真实采样时点和当前操作就绪范围；沿用原后置执行校验，超时仍为 unknown。
- 插件：`run` 先核对 unknown，再初始化旧路线债务关联；`step` 以当前 SDK 事实投影待测清单，`selectObligation` 有限优先当前工作，`scheduledRecovery` 从保留源检查点发起严格恢复或具体目标恢复。
- `obligation-scheduler.ts` 保存轮换、路线与欠缺原因，不能授权动作。恢复后的观察决定真实位置；到达只使目标可候选，实际执行仍核对当前许可和覆盖。
- source 读取缓存每次选路最多保留 8 份；当前语义索引在同一步同步调用内共用，经过 await 恢复后重建。没有跨观察缓存执行许可；没有承诺大页整体线性成本。

仍没有多路径全局最短成本规划，不能恢复任意 JS 堆和外部状态。旧债缺少可核验对应时会保守推迟可能有效的恢复；这是一项显式缺口，不会静默删掉目标。原始计划、历史观察、失败证据仍保留，长期体积收敛尚未证明。

## 验证边界

实际覆盖以独立页面事件为准，任务完成状态、恢复成功返回值和队列清空分别记录。unknown 使用明确的持久化结果丢失故障注入，要求原记录继续为 unknown，冷重启后在新观察、新会话和派发之前阻断。失败恢复保留未测项，不能以新会话可用为由改记成功。
