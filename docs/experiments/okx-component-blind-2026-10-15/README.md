# OKX 评分组件：GPT-5.6 盲测与身份模型审计

2026-10-15，基于 `fix/identity-disambiguation` 的 `bfe0908`。本轮增加实验与记录，未改变生产匹配规则，未点击评分或提交投票。

## 结论

程序尚未达到上限。当前规则擅长给单个 DOM 控件建立对应，但缺少“一个逻辑组件包含多个操作节点”的模型。对五颗星，合理的建模是一个评分组件、五个可选择档位，以及各档位到当前 DOM 按钮的绑定。把五个按钮直接合并成一个 `identityId` 会破坏现有一对一契约，也会丢掉各档位的执行目标。

已有材料足以让本次 GPT-5.6 判读出星级组件，但不足以确认所有跨刷新对应和点击副作用。需要分别表达组件语义、当前节点定位、业务值和历史身份；不能把模型“看懂”直接等同于可以安全自动执行。

## 盲测设置

- 实际子代理：`gpt-5.6-sol`，`low`，`fork_turns=none`。只允许读取独立 public 目录，没有给出“评分”“星星”等类型提示，也没有给标准答案、源码或父代理分析。
- 使用现有 `prepareIdentityReview` / `includeIdentityImages` 导出原样 `identity-review/1`，仅把嵌入图片无损解码为 PNG。
- 同一个真实组件，首次出现和刷新后各五项，共十项裁决材料、三张不同观察截图。不是十个独立组件样本。
- 派发前冻结输入 SHA-256 和验收条件；模型只作答一次，没有反馈答案后重试。
- 访问使用独立未登录 Chromium，只关闭地区提示、观察和刷新。模型不访问网页，不执行动作，也没有写回裁决。
- 隔离依赖子代理文件读取约束，不是操作系统级权限隔离。

## 模型实际表现

| 问题 | 实际结果 |
| --- | --- |
| 组件是什么 | 独立识别为五段星级评分/投票控件，组件识别置信度高 |
| 五个按钮的关系 | 一个逻辑组件内的五个不同 DOM 节点 |
| 每个按钮代表什么 | 推断左到右为 1～5 星，明确指出没有显式 `value` / `aria-label`，映射置信度中等 |
| 首次观察的身份裁决 | 5 项 `independent`，列出的候选均为同时存在的其他节点 |
| 刷新后的身份裁决 | 5 项 `uncertain`，拒绝只靠位置、序位、外观认定历史身份 |
| 点击的业务影响 | 不宣称已知，指出缺少提交行为、后果和可逆性证据 |

十项关系判断都符合当前保守身份契约；这不表示十项跨刷新对应已经解决。模型看到了三个观察的图片，并指出目标原始观察中的地区弹窗遮挡。原始观察是正确的历史材料，但首次五项的 `current` 只提供存在/换绑信息，缺少当前目标的完整视觉和命中状态，不适合直接做当前执行判断。

还发现一个接口问题：模型引用了真实的 `image:<observationId>`，而 `identityDecisionCommand` 只接受 `target`、`timeline`、`current`、`candidate-N`。因此十项原始输出都无法直接通过命令构造器。离线移除图片引用、保留其他合法证据引用后，五项可构造独立记录命令，五项不确定返回无命令。此归一化仅作核验，未修改原始回答、未执行命令。后续应统一导出说明、模型输出 schema 与校验器的引用规则。

1. 实际 DOM 中五个按钮名称、value、ARIA 评分语义为空；共同祖先包含 `RatingStar` / `RatingVote` 类名，完整子树包含星形图标以及邻接的 `4.7`。完整 DOM 已经被采集，但现有裁决投影主要给出目标和祖先，没有直接组织出组件及其子节点。

## DOM 标记能解决什么

现有采集器已经用 `WeakMap<Node, instanceId>` 为活着的 DOM 节点分配实例编号，执行前会核对目标实例。因此增加 `data-agent-id` 可以简化某些定位流程，但不会自动生成评分含义或跨重建对应。

- 节点移动：实例编号可以保持，无须重新识别。
- 节点删除重建：新节点没有旧的外部 WeakMap 项；由运行时写入的属性也不保证被应用重建逻辑恢复。
- 节点复用：实例编号可保持，但其表示的记录或业务值可能已变，仍需绑定检查。
- 节点克隆：HTML 属性可能一并被复制，注入的属性可能重复，需要唯一性检查。

由我们控制的网站可在源码中输出稳定业务键及正确的可访问名称，例如组件键、评分值和标签。第三方网站则宜把模型判断保存在外部语义记录中，记录来源、证据和有效范围；如为定位注入临时属性，应与页面声明分开，不能再次把自己写入的标记当成独立证据来提高确信度。直接修改 React 私有 props 也不会建立可靠身份契约。

## 下一步优先级

1. **组件模型**：增加逻辑组件和成员关系，让评分表达为一个组件与五个档位，保留五个 DOM 执行目标。逻辑动作可表示为 `setRating(3)`，它是建议的抽象，当前引擎尚无此接口。
2. **证据投影**：按组件组织局部截图、公共祖先、子树/图标、选中态、显式值、当前命中状态及时间线；避免十项材料重复携带大量页面正文。此次原始 JSON 约 5.85 MB。
3. **主动消歧**：优先使用允许范围内的悬停等探测，把前后差异变成证据；会提交数据的点击单独处理。
4. **模型输出与验证**：模型提出组件类型、成员角色和动作值，程序检查节点是否仍存在、绑定是否变化、目标是否唯一，并根据模型类型分别处理节点身份与逻辑档位身份。统一图片引用格式，避免有意义的回答无法被接口消费。
5. **可选增强来源**：应用提供的稳定标记最可靠；框架组件信息可作为补充，但必须注明版本、来源与缺失情况，不依赖私有实现作为所有网站的默认契约。

五颗星建模为一个复合评分控件也与 [W3C 的评分 Radio Group 示例](https://www.w3.org/WAI/ARIA/apg/patterns/radio/examples/radio-rating/)一致：组件内仍保留具有各自评分标签和选中态的选项。这是组件语义，不是把多个 DOM 节点合并为同一个节点身份。
