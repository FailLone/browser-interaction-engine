# 区域划分的显式条件复用

日期：2026-10-15。分支 `codex/region-review-reuse`，产品实现 `9662982`。

## 实现与边界

上层在区域审阅中声明 `reuse: {binding: "same-url-context", businessScope}`。返回相同准确 URL 和已知声明上下文，或节点重建后，引擎提供当前匹配材料；上层显式调用 `reuseRegionReviews`，才会生成绑定新文档、当前候选和成员的新区域划分，并保存来源链。

新的区域探索组重新待决，不继承旧 all/sample/defer/skip。控件用途仍需独立审阅或复用，列表与目的页决定也独立。每次自动派发继续校验当前目标与适用条件；撤回源判断会使有效派生区域及其探索组失效。单项 execute 保持上层接管语义，不能用它验证 DFS 深度门控。

首版比较完整候选池与原选择子集，包括容器/成员祖先、显式标签、标题、操作依据、输入约束、表单端点和列表记录绑定。即使只选择一个成员，其宽锚点中其他成员改变也会阻止复用。歧义、关键观察缺口、活动弹层、未知上下文、超过证据上限、跨 URL 或跨会话均不复用。SDK/HTTP、hook 材料和持久事件已接入；尚无专用复用 UI 面板。详见[协议](../../REGION-REVIEW.md#返回页面后的显式划分复用)。

第一版区域只纳入 Markets，却绑定 24 成员 Main menu。首次返回后，未被选中的搜索框生成了不同的 id/name/selector，完整候选池不再相同，因此 `reuseCandidates=[]`。这是一项保守限制，不能据此声称复用成功，也不能静默忽略这些条件。
