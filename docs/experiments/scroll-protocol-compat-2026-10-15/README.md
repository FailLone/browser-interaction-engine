# 两种滚动动作协议的方向延续

日期：2026-10-15。分支 `codex/scroll-traversal-protocol`，独立修复提交 `a6ed79a`。基于本任务的区域复用分支，合入规则任务已提交的 `4eecfc3`，不改规则判断逻辑。

## 问题与修复

原方向排序只识别页面的相对数值滚动及控件的 `{x,y}`。规则分支把页面动作改为 `source=scroll-traversal`、绑定文档及容器的绝对坐标协议后，方向延续不再生效。规则任务报告的页面中部起点位置为 `[1370,1370,1820,2270,2720,3170,3600,3150,3600]`，没有到达顶部。

现在两种协议各按实际目标分组，绝对协议使用共享 schema、文档/容器 ID、当前容器快照、预期起点、尺寸及滚动范围核对动作。历史动作必须与同一容器的真实前后位移同轴同向；容器丢失或歧义、边界变化、过期位置、范围变化、失败尝试和错误位移不会提供延续依据。外部检查探测不作为自动滚动的方向历史。

只重排已经通过权限/范围门控的当前候选，其他控件和其他容器保持原优先级位置。不会恢复缺席、排除或暂缓的方向，不改变用途、深度、检查结果和重放权限。
