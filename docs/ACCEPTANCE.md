| 排除与预算 | 排除提交不执行，动作预算耗尽后仍有 pending 项 |
| 并发控制 | 竞争 SDK 写请求串行；API 与 SDK 共享会话；界面操作走 API |
| SSE | 持久化游标续读、去重、服务关闭时结束活动流 |
| Hook 异常 | 输入插件失败记录错误并阻断对应操作，其他动作及检查继续 |

## 分层重构验证

- 项目已移动到 `~/Projects/browser-interaction-engine`，旧数据库和证据目录一起移动。
- core 只依赖 zod 和纯 JavaScript 哈希库，使用 ES2023 独立类型检查，无 DOM、Node 类型或模块导入。
- 非网页计数器通过 core + 内存插件完成执行、幂等、DFS、预算、状态归并和检查点恢复。
- SQLite 和内存插件共用 8 项存储契约测试：副本隔离、不可覆盖观察、事务回滚、事件游标、中断恢复及二进制证据。
- 浏览器 + 内存模式通过 HTTP 证据查询，截图不依赖文件路径。
- 浏览器组合层可读取旧流程范围字段，原有操作引用保留。
- 架构测试限制 core 的依赖方向，HTTP 留在应用层。

## 验收边界

这些结果验证本地受控场景和 V0.1 观察契约，不表示任意网站都能完整探索。未支持的浏览器能力、未知业务有效性、身份歧义以及无法恢复的业务副作用继续由证据、缺口和结果状态表达。实际报告中的 0 个未知动作只描述那一次运行。

核心包和服务不存在测试站标签、交易对或控件 ID 的硬编码。示例和测试中的应用相关选择由调用方负责。后续能力按 [ROADMAP.md](../ROADMAP.md) 迭代。
