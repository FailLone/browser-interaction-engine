# 控件身份匹配与人工确认

本次增强保留 `ControlIdentity`、`IdentityHypothesis` 和 `resolveIdentity` 接口，给 `Control` 增加可选的 `identityContext` 证据。检查协议、事件投递及证据存储不变，旧观察仍不可覆盖。

## 重复组件与局部语义

`data-testid` 可以是组件类型而非实例标识。稳定键在当前或历史记录中重复时，匹配器用适配器语义签名继续细分：不同问题文字的 FAQ 按钮可以各自沿用记录；同名同键按钮继续待确认。缺少名称的历史候选不会因信息缺失被当成已排除。唯一的稳定键仍可承载名称变化，例如 Show → Hide。

浏览器采集器还提供 `identityContext.scope`、`identityContext.binding` 和证据来源：

- 命名祖先、fieldset/legend、前置标题、明确的祖先 ID 和页面地标提供局部作用域。数字槽位和常见生成 ID 不作为祖先依据。
- 链接地址与 target 提供目标绑定；相同文字指向不同地址时分别追踪。
- 单个字段附近的短描述可以区分 BTC/USD 等同 placeholder 输入框。输入值、纯数字、隐藏弹出内容和搜索结果不参与字段描述；超长或截断证据直接放弃。
- 组件内部只有一个有绑定的字段时，嵌套搜索框可继承其所属字段关系。展开、筛选和收起弹层不会用选项文字替换搜索框身份。
- 无名称容器可以采用唯一直属控件的显式可访问标签。完全相同的评分按钮仍不凭顺序或坐标猜测。

上下文是页面可观察证据，不是业务身份保证。它不提升操作能力、业务用途或可逆性。上下文变化会失效原有对应和人工判断；列表记录继续按下述记录键规则处理，不用祖先槽位代替记录身份。所有指派仍经过整批一对一冲突检查。

观察规范版本为 `observable-v4`。旧观察保留原有版本与内容；升级后不会用新规则回填旧证据或清除旧 pending。跨版本缺少上下文时保守建立新记录，历史裁决仍可审阅。`stableKey` 本身及基于它的调用方规则保持不变。

## 列表记录的识别

浏览器适配器把列表项的记录依据组合到已有的 `stableKey` 字段中。列表外仍使用原来的 `data-testid`、`id`、`name` 规则；列表内采用以下依据：

1. 列表项的 `data-row-key`、`data-item-key`，或语义列表项上的 `data-key`。
2. 没有声明记录键时，使用列表项标签或去掉按钮、输入框等交互内容后的完整描述文字。描述超过 500 个字符时放弃，不截断成可能碰撞的键。
3. 将记录依据与列表作用域、嵌套父项以及项内控件的局部标识组合。项内优先使用 `data-testid` / `name`，否则使用控件名称、类型和角色。

同一列表的 A、B 两条记录可以各有一个名为 Edit、`data-testid="edit"` 的按钮；它们会分别追踪。重排、重新渲染、移出可见窗口后重新出现，只要记录依据不变，就能沿用各自的身份。

列表项自身的 DOM `id` / `data-testid` 可能只是虚拟列表槽位，不能单独作为记录身份。匹配不使用数组索引、行号、截图坐标或输入值。虚拟列表复用同一个节点展示另一条记录时，记录键改变会建立另一身份；旧人工判断也不会跨这个变化继续生效。

自动提取的组合键是可观察证据，不是业务身份保证。描述文字相同、缺失或变化时可能仍产生歧义或新的身份；若虚拟列表完全不暴露记录区别，引擎不能凭空知道业务记录已切换。最可靠的页面支持是提供稳定、唯一的记录键。列表内 `stableKey` 的值会变成组合键，依赖旧裸 `testid:` / `id:` 值的匹配规则需重新检查；字段和命令格式不变。

## 整批匹配与冲突

- 整次观察基于同一份历史记录规划匹配，再统一提交，避免先遍历到的控件抢占记录。
- 带标识的控件仅与区域、角色及标识兼容的记录匹配，不退回到另一个标识下的同名控件。
- 没有标识时，仅在当前控件和历史候选都唯一、且有名称、标签或适配器局部语义依据的情况下自动匹配。
- 同一项里相同局部标识的重复控件继续产生歧义；重复记录键也不会任意挑选。
- 同一次观察中，一个身份最多对应一个控件。冲突的人工判断会重新进入待确认状态。
- 尚未解决的歧义在绑定未变时保留；人工判断也仅随兼容的元素实例沿用。元素重建后可能需要再次确认。
- 已人工关联到其他身份的临时记录不再作为独立历史候选，减少重复候选造成的假歧义。

## 在界面中确认

“身份”是跨观察追踪同一个控件的记录。“身份歧义”表示引擎无法确定应该沿用哪条记录。依赖历史身份的操作受到限制；controls 探索模式仍可通过当前节点实例执行经检查允许的操作，不因此获得历史重放资格。

顶部同时显示当前观察与全会话累计待确认数量；详情另外显示当前有操作能力的歧义控件与历史待确认记录。当前数量降低不会删除、解决或隐藏旧记录，也不能解释为实际受阻操作数或整页测试完成率。

在“身份与歧义”页选中一项，依次查看原因、目标控件和相似候选。局部截图的橙框标出具体控件，可以展开查看整页位置。目标使用歧义发生时的观察；候选优先使用同次观察，否则使用歧义发生前最近一次记录，时间始终可见。截图过期、缺失或控件不在视口内时明确显示限制。

- **这是独立控件，单独记录**：有证据排除列出的全部候选，各自保留身份和操作记录。这不证明不存在未收集到的历史对应。
- **这是候选 N，沿用它的记录**：有证据证明是同一个控件，把本次控件关联到所选历史身份。
- **证据不足，暂不确认**：说明还缺什么信息，保持 pending 和操作限制。此选择不发 resolveIdentity，不写修订、不增加事件；说明仅在当前页面显示，刷新后不会保存。

默认不选择任何关系。发生时同时存在的不同控件、当前被另一个控件占用的身份，以及无法读取原始记录的候选不能选择。目标实例已不在当前观察或检测到换绑时，禁止应用旧判断。无法判断时应明确选择“证据不足”。

填写理由并点击“保存身份判断”，仍调用原有 `resolveIdentity` 命令。系统记录来源、时间与理由，重新观察当前页面并检查操作可用性；不点击或填写目标控件，也不自动恢复 DFS。确认结果留在当前卡片，技术编号和修订原文收在折叠区。

## 可交给人或模型的同一份材料

客户端 `prepareIdentityReview` 从现有只读接口整理 `identity-review/1`；UI 使用同一投影。没有新增服务器检查协议、命令、事件或存储格式。

材料包含目标与每个候选的观察时间、页面与区域、值和位置、控件 DOM 属性、祖先记录属性、标签关联、页面文字，以及已记录的前序操作。候选使用歧义时或之前最近的观察，禁止用后来修改的 `lastControl` 或当前 DOM 回填历史。原始观察缺失时不替代；截图或详细记录过期、DOM 截断时保留缺口。没有记录触发操作时明确表示未知，不能从两张图推断重排原因。

`includeIdentityImages` 用原有 artifact 接口嵌入实际截图字节，失败时记录 unavailable；导出文件无需保留原会话服务器才能查看图片。截图旁有目标/候选矩形和所属观察编号。页面提供的文字和属性只作为不可信证据，不能作为给裁决模型的指令；属性稳定性、唯一性仍需依据页面契约或其他可靠证据判断。

`identityDecisionCommand` 校验来源、证据引用、候选资格和当前已知换绑状态，把确定结论转换成既有 `resolveIdentity` 命令；uncertain 返回 undefined。它只做结构及冲突校验，不是语义正确性证明。调用方提交前应重新生成材料；UI 已这样处理。此客户端读取流程不是跨多个请求的原子快照，外部集成应暂停探索后审阅；最终执行仍以服务器现有检查为准。

**“待确认数为 0”不代表全页面均已正确识别。** 必须同时说明遍历范围、未访问分支、身份相关阻塞和证据缺口。相同外观、同一槽位、相同坐标都不能恢复客观上缺失的历史对应。
