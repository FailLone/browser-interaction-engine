# 持续更新页面的遍历

`controls` 模式不要求页面达到视觉静止。实时展示仍写入原始观察、DOM 证据和截图；控件覆盖只比较与操作相关的投影。完整 `canonical` / UIState 和严格检查点继续保留数据变化，不以覆盖相同冒充业务状态相同。

## 通用判断依据

实现不含站点、域名、币种、控件名称或站点 CSS 特例。默认区分以下情形：

- 已有的纯展示、只读输入，以及没有受支持操作的图表容器，不进入可操作控件稳定性比较。Canvas 内部继续报告覆盖缺口，图表绘制变化不是已经测试了图表交互。
- 列表项优先使用显式记录键。缺少记录键时，使用该列表中唯一的有效 HTTP(S) 链接目标集合；链接集合相同的多项不能用此方法合并，退回原来的描述证据。行号、位置和可复用节点 ID 不作为记录键。链接改变时重新判定绑定。
- 没有链接或声明键时，描述性记录键可排除被动的货币/百分比显示子树，前提是剩余描述包含文字且在同一列表中唯一。纯数字记录 ID、显式标签及交互控件不按此规则排除；投影后重名则退回完整描述，不合并业务对象。
- 对有文字名称、目标明确的原生链接，被动的货币/百分比格式叶节点可直接作为展示读数；其他数字叶节点需在连续无引擎动作的采样中至少变化两次。格式明确的慢速读数也不必等待它先更新两次。链接必须仍有非数值名称；表单、下载、按钮/输入/选项等交互后代和改变的显式标签不适用。识别证据保存在 `control.liveContent`，原 `name` / `displayedText` 不改写。
- 链接目标或显式标签变化会重新学习；数值叶节点变成业务文字时撤销投影。动作开始时重置未确认候选的连续采样计数，避免把多次点击结果当作自主刷新。已经确认的展示资格只在原绑定和数值格式仍成立时延续。

这不是“任何持续变化都可忽略”的规则。没有可识别的语义或稳定绑定的自定义组件继续保守处理；不能仅通过更新频率推断业务无关性。

## 检查如何一致工作

身份签名和覆盖样本使用上述交互名称，列表键不包含报价。稳定性采样和执行前检查使用同一交互投影；完整原文仍用于证据和严格状态比较。`stateful` / `representative` 不自动启用实时文本投影。

执行前仍比较文档、URL、节点实例、记录键、控件结构、输入值、选择、约束、展开状态、操作依据和遮挡。声明的业务上下文每次重新读取，即使该节点已被识别为展示。非界面操作仍验证目标原始文本。

几何位置从全页面静止条件移到所选动作目标的执行前检查：其他控件移动不使当前目标失效，目标移动、替换或遮挡仍触发重新验证。实际执行继续使用原生定位及可操作性检查。`preflight(observation, action?)` 的第二参数可选，已有第三方驱动兼容。

版本标识为 `observable-v3-live-v1`，控件抽样策略为 `browser-controls-live-v1`。旧观察不改写，新旧覆盖样本不静默合并。

## 防止反复观察

会话持久保存 `observationFailures`：连续观察不完整，或执行前页面/上下文失效，均计数。达到 3 次后暂停，停止原因 `OBSERVATION_NO_PROGRESS`，并发出 `exploration.no_progress`。同一次新观察不重复计数。

在动作尚未派发的情况下，controls 模式可使用新观察重新验证同一待办；只重试读取与验证。已成功、失败或结果未知的动作不因此重放。恢复 DFS 或额外获取一张完整截图不清除执行前失效的计数；之后仍失效会立即再次暂停。一次成功操作清除计数；纯采集不完整的问题在完整观察确认后也可清除。

界面区分采集不完整和连续无进展，不把反复点击“重新观察”或单纯延长等待作为解决方案。未执行和未知项始终保留覆盖缺口。

## 验收

`tests/live-content.test.ts` 使用独立 HTTP 页面和真实浏览器，不依赖外网、行情站点或应用专属配置。每 10 ms 更新的数值和 Canvas 从开始到结束不停止；两组不同名称、顺序的页面均应执行全部有限控件且每项只执行一次。

负向测试覆盖共享链接不能混同记录、列表重排与节点复用、按钮/输入/显式标签的持续变化、声明业务上下文、严格状态模式、无进展暂停及恢复、目标移动与遮挡、已识别读数变成业务文字。原观察生命周期测试继续验证未知动作不重放以及采集故障解除后恢复。
