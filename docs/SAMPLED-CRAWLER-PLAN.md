# 抽样遍历器（Sampled Crawler）计划

分支：`claude/traversal-blockage-investigation`。起点 `f00fc35b`（旧插件修补，作为对照基线）。

## 背景与结论

2026-10-19 用 `https://www.okx.com/convert/usd-to-btc` 实测：

- 旧插件 240 秒只执行 12 个命令，782 条待办完成 6 条，模型 0 次调用。
- 大部分时间花在执行前证明（3756 次 SDK 调用，浏览器点击仅 4.8 秒）。
- 约 4 次点击后就离开入口页，在各页面的导航菜单里打转；同一列表/价格变化不断生成新待办。

原因是"穷尽 = 可证明地穷尽"的定义：任何不能证明等价的东西都成为永久义务，真实站点上永不收敛。

## 新目标

"穷尽"的含义改为：**像真实用户一样，在给定范围内把页面的各种状态尽量交互出来，让 UI 问题暴露**（类似 Crawljax）。

- 同类东西测一个或几个即可（列表项、同模板卡片）。
- 易变内容（价格、时间、百分比、计数）不构成新组件或新状态。
- 完成条件：范围内每个"状态 × 动作类别"至少执行 k 次，或预算用完。
- 大模型是插件：程序判断不了的疑问先问 JEV（便宜），JEV 拿不准再问 LLM；答案直接生效并缓存。
- 以后用"目标模式"代替穷尽：LLM 生成范围/路径/任务，JEV 判断相关性。

## 设计

新包 `packages/crawler`，只复用适配器的页面抓取（`BrowserEngine` 的 observation / actions / execute）和 `rules`，不经过旧插件的义务账本与证明链。

1. **状态归类**：URL 路径 + 打开的弹窗/浮层 + 可交互控件骨架（角色、类型、去数字后的名称）。价格等数字统一屏蔽。
2. **动作归类**：动作类别 = 状态无关的 (区域路径, 角色, kind, 去数字名称)；同一结构化列表中的项归为一类（`structuralItem` / `list`），每类抽样 k 次（默认列表 2 次，其它 1 次）。
3. **调度优先级**（高→低）：
   1. 当前打开的弹窗/浮层/菜单内部动作；
   2. 入口页正文动作；
   3. 本页内会改变状态的控件（tab、展开、hover 菜单）；
   4. 页头/导航菜单（全站一次，仍在本页）；
   5. 同站同范围的跳转（当前页没有页内动作后才发生）。
   离开范围的链接不执行。
4. **蒙层处理**：弹窗打开时只在弹窗内部选动作；若弹窗内没有可执行动作，先尝试关闭（关闭按钮 / Escape），而不是在被遮挡的背景上反复失败。点击被拦截的动作记为一次失败，不重试同一类。
5. **回退**：需要回到某状态时，从入口 URL 重放记录的动作路径；失败则放弃该状态剩余动作。
   - 2026-10-19 调整：默认只测当前页。离开当前页的跳转在发生前被拦截并记录（不加载其它页面）；hash / pushState 这类同文档路由变化记录后撤销，低优先级再测或放弃。进入其它页面继续测改为可选（`followNavigation`）。
6. **安全策略**：一份允许操作 + 禁止项（登录、注册、交易、提交、外站、下载）。单层检查。
7. **规则 hook（可选，默认关闭）**：每进入新状态可运行检查。当前以遍历为主，不以发现问题为验收目标。
8. **模型插件（步骤 2）**：疑问队列，JEV→LLM，按材料哈希缓存，答案直接生效。

## 分步实施与验收

| 步骤 | 内容 | OKX 验收（240 秒） |
|---|---|---|
| 1 | 纯程序抽样遍历器 + 运行脚本 + 指标 | 只测入口页时 ≥70% 动作在入口 URL 上，宽范围时入口页的页内动作在任何跳转前完成；弹窗打开时先处理弹窗；同一列表最多执行 k 次；不同状态数可报告 |
| 2 | 模型判疑（JEV→LLM，缓存） | 模型实际被调用；待定控件被分类后可执行 |

## 第二阶段（2026-10-19 用户反馈）

目标不变：以遍历为主，在给定范围内尽量把页面状态交互出来。本阶段补齐交互手段、降低模型成本、能量化覆盖。顺序 4a → 4f，每一项完成后在 OKX 实测并写入实验记录；未达标如实记录。

### 4a 模型计费与统计

- 每次 JEV/LLM 调用记录：用途、token、耗时、`usage.cost`（JEV 只收输入费，$0.042/百万 token，返回自带 `usage.cost`；LLM 费用字段需实测确认，拿不到则按配置单价估算并标明"估算"）。
- 修正缓存统计：批量提问的首次答案不再记为缓存命中。
- 汇总报告分列 JEV / LLM 的调用次数、金额、平均耗时，以及缓存命中数。

验收：OKX 运行结束后可直接读出两者的次数和金额；本地测试覆盖计数口径。

### 4b JEV 提问优化，减少 LLM

依据 TypeSafe 文档与社区指南：

- 把控件事实放进 `state` 的命名字段（标签、角色、标签名、指针样式、事件线索、父元素、附近文字、关联弹出层），问题按字段名引用。
- 问题拆细，每个只问一个性质，并写 `criteria`（什么算是 / 什么算否）。
- 同一状态的所有问题一次请求（JEV 内部各题独立并行）。
- JEV 不确定时不再默认问 LLM：对遍历来说"点一下看结果"更快更便宜更准，所以不确定的弱控件直接试点一次（受同样的安全策略和配额约束）。LLM 只用于生成类任务（目标规划、输入样例）和有风险的判定。
- 记录 JEV 概率分布，确认 0.4–0.75 的集中现象是否消失。

验收：同一 OKX 配置下，LLM 判定调用降到 ≤3 次（原 24 次），被确认可交互的弱控件数不低于原来的 19 类，总模型金额下降。

### 4c 输入框分类

- 先用结构线索判断：`type`、`inputmode`、`pattern`、`min/max/step`、`role=searchbox/combobox`、`aria-autocomplete`、关联候选列表、占位文字、标签。
- 线索不足时一次 JEV choice（数字 / 搜索 / 邮箱 / 日期 / 任意文本 / 其它），结果按"输入框类别"缓存。
- 输入后的页面反应作为纠正证据（例如数字框过滤掉字母）。

验收：OKX 兑换页金额框判为数字，页头/帮助中心搜索框判为搜索；本地夹具覆盖各类型。

### 4d 输入与 hover

输入值来源：程序生成候选，JEV 选择或判定，页面验证。

- 搜索：至少两个值。一个"能搜出来"的（取当前页面已出现的词，如列表中的币种名），一个"不可能存在"的（如 `zzqx-no-result-7319`），用来暴露空状态。
- 数字：合法值、边界值（min/max）、0、非法字符。
- 其它文本：按类型、长度、格式生成；语义不明的输入框类别由 LLM 生成一次样例并缓存。
- 输入值作为动作类别的一部分抽样，每类输入框有配额；回车/提交只在安全策略允许时执行（搜索可以，表单提交不行）。
- hover 扩展到有悬停提示、`aria-haspopup`、或指针样式加事件线索的控件，同样按配额。

验收：OKX 上至少执行一次数字输入和一次"无结果"搜索，并观察到对应的新状态（换算结果变化、空状态）；hover 菜单被打开。

### 4e 同组模式切换的自适应抽样

- 同一组 tab/radio/选项先点一个。点后页面结构和文字（屏蔽数字后）都没有新内容，说明它只影响 canvas 等无法深入的区域：同组其余成员跳过。
- 出现了新内容（如价格页的 About / Price / News）：继续测同组其他成员。

验收：OKX 图表 1h/1W/1M 只点一个；价格页的内容标签页逐个点到。

### 4f 加长时长与覆盖量化

- 新增覆盖指标：每页"发现的控件类 / 执行过的控件类"、出现过的页面文字占比（按文本块统计）、不同状态数随时间的增长曲线（判断多长时间后不再有新状态）。
- 在 OKX 上跑 10 分钟和 30 分钟，宽范围与只测入口页各一次。
- 规则检查作为附带观察打开，记录报出了什么，不作为验收目标。

验收：报告给出各页覆盖率、新状态增长曲线与饱和时间、模型总金额。
