# 独立自主探索插件

功能位于 `packages/explorer-plugin`，分支为 `codex/autonomous-exploration`。SDK、core、浏览器适配器及原有客户端源码不变。插件只使用现有公开接口，应用服务和调试页面负责加载它。

## 启用与配置

插件默认关闭。复制 `.env.explorer.example` 为 `.env.explorer.local`，配置 JEV 和 LLM 的提供商、完整接口地址、模型及密钥，然后运行：

```sh
node --env-file=.env.explorer.local --import tsx --conditions=development apps/server/src/main.ts
```

调试页面可以通过原有开发入口启动；构建后也可由应用服务直接提供。使用 Node.js 24。密钥仅保存在后端环境中，不会返回调试页面。

JEV 支持 TypeSafe SystemOne 和 OpenRouter Decisions；LLM 使用兼容 Chat Completions、支持 JSON-object 响应的服务。还可以通过 `Provider` 接口注入其他服务。新计划、输入样本和用途描述需要 LLM 生成；已有候选的判断优先 JEV，并按判断用途处理不确定结果，不统一升级 LLM。JEV 未配置、格式错误或服务不可用时仍可转交 LLM，并保留具体原因。

没有真实配置时可以查看页面与历史，任务会明确提示需要服务配置；产品运行不会自动使用测试模型。

## 使用流程

1. 在左侧“探索工作区”填写起始网址，选择“自主探索”，输入目标并展开“探索预算”设置额度，点击“创建探索任务”，再点击“开始 / 继续探索”。切换到“手动探索”可使用原有流程。
2. 开始探索后，在“遍历路径”中查看程序、JEV、LLM 和实际执行节点。点击模型节点后，右侧显示“输入 / 输出 / 决策影响”：实际请求体（不含认证信息）、返回内容、采纳状态、具体审阅命令、计划修改和关联的实际动作结果。历史未记录的信息会明确标为不可用。
   直接点击左侧历史会话也会加载所属探索任务；路径仅展示所选轮次，并显示本轮 JEV / LLM 次数。“查看最近调用”可直接打开最新请求的详情与转交原因。
3. 主区域的“探索计划与未完成范围”显示未完成范围、未选样本、原因、进入条件和证据；这些记录保存在独立 SQLite 文件中。服务重启后先暂停，继续时重新观察。
4. 选择需要补测的范围，设置为新的补测计划，再开始下一轮。也可以调整目标或编辑模型提出的范围。

旧条件范围升级时，程序核对每份保留来源，把一条旧范围拆成条件明确的待测子项；无法核实的来源另保留受阻缺口。原范围显示“已拆分为子范围”，保留证据和转交关系，不计为成功或未测重复项。选择补测时应选择具体子项，不能重新启用已经转交的粗范围。迁移不会调用模型，也不会以当前页面替换遗失的历史来源。

`conditionMigration` 保存策略版本、原条件、来源和子项清单；子项的 `conditionLineage` 指向父项。只有实际执行或 SDK 验证的历史覆盖才能完成子项。子项或来源关系损坏时，原范围恢复为待核实缺口；unknown 执行结果优先阻断恢复和迁移。该机制只处理有保留来源的旧未执行范围，不生成未观察过的模式组合，也不重写历史成功。
5. 默认预算为 3 轮、300 次动作、30 分钟、300 次模型请求。预算耗尽后在左侧“调整任务”中显式追加；已有用量与历史不会清零。

暂停和接管会停止新的模型调用与操作派发；已经交给引擎的命令先收尾。插件运行期间，普通 DFS 和其他修改会话的请求被应用层阻止。只读查看正常可用。

## 判断结果的边界

- “当前计划完成”表示约定范围的实际操作已经验证，仍不代表全站穷尽。未选样本保留为未测。
- 下一轮重新匹配目标、审阅区域和操作，不使用旧控件 ID。历史成功仅用于调度参考，并检查声明上下文与已捕获的操作条件；不会写成本轮成功。
- 执行结果未知时不自动重放。同名且无法区分的目标、证据缺失、恢复未验证都会保留为缺口。
- SDK 没有公开提供的操作会显示能力缺口。例如当前宿主未公开某些边界外点击退出能力时，插件不会直接操作浏览器绕过它。
- 完成标准目前验证受支持交互及其后续观察；任意业务断言不由模型口头判为成功。

## 调用失败与排查

OpenRouter 示例配置固定上游 `Alibaba`，采用 `low` 推理量和 8192 输出 token 上限；分别由 `EXPLORER_LLM_UPSTREAM_PROVIDER`、`EXPLORER_LLM_REASONING_EFFORT` 和 `EXPLORER_LLM_MAX_OUTPUT_TOKENS` 调整。模型与接口沿用 ui-sentinel；输出额度按本项目生成结构化计划的需要设置。请求时限仍由 `EXPLORER_MODEL_TIMEOUT_MS` 控制，默认 60 秒，没有隐藏重试。

超时不表示已经收到模型结果。首次计划生成失败后保留失败记录，继续时重新生成计划，不把错误信息当作探索范围。输出被截断会标为 `MODEL_OUTPUT_TRUNCATED`，保留返回内容供排查，但不用于执行。

2026-10-15 对用户失败任务的同一页面证据复验：原调用 60 秒超时；补齐上游路由、压缩初始计划和调整输出额度后，23.48 秒返回 5 项有效计划。该复验只重新生成计划，没有自动执行用户页面动作。专项测试增至 25 项通过。

## JEV 优先与 LLM 调用边界

| 判断 | 处理方式 |
| --- | --- |
| 下一步、代表样本的候选排序 | JEV 排序；不能区分时程序按固定顺序选择，仍检查范围、操作依据和时效，不为排序升级 LLM |
| 区域与探索范围分组 | JEV 使用单独的分组门槛，默认 0.65；可由 `EXPLORER_GROUPING_THRESHOLD` 调整，不授予操作权限 |
| 控件分类、身份、操作授权 | 保留默认 0.8 门槛；必要的歧义判断仍可交 LLM；明确缺少操作依据时保留缺口 |
| 已有未完成范围、覆盖计数、实际成功 | 程序保存并核对执行证据，不需要 LLM 重写或口头判定 |
| 下一轮计划 | JEV 先判断是否缺少新范围或前置操作，明确需要时才生成新计划；否则沿用已有缺口 |
| 初始计划、新输入内容、新用途描述 | LLM 生成，并经过结构与执行前校验 |

分组门槛与排序规则不降低操作授权、身份校验或范围限制。JEV 原始回答与程序采用的候选分别保留，右侧“决策影响”明确显示由谁作出最终选择。置信度是选项分布的集中程度，不是正确率保证；门槛须结合场景验证，参见 [TypeSafe 置信度文档](https://docs.typesafe.ai/confidence)。

会话 `8623f14b` 的原记录包含 17 次 JEV、16 次 LLM，其中 14 次为转交、2 次为生成。用同一批已保存回答离线重放新路由，转交从 14 次降至 2 次（两次控件分类）。该结果仅验证路由节省，不是重新遍历，也不保证新路径有相同调用数；复验没有新增付费调用。
