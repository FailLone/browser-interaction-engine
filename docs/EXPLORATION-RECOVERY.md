# 代表性探索与基础恢复

浏览器新会话默认使用 `exploration: 'representative'`。它以明确的抽样范围安排工作，不承诺穷尽页面。`stateful` 保留原有逐状态探索；未保存 exploration 配置的旧会话也继续使用逐状态语义。纯 core 的默认配置仍是 stateful，平台适配器可以提供抽样策略。

## 探索范围与证据

代表性样本按逻辑控件、操作、目标输入、业务上下文、URL、弹层范围、可见控件结构及目标控件约束/选项/可操作条件区分。填入不同普通值不会复制其他控件的整套待办。输入边界、不同字段起始值及所有控件组合并未因此得到完整测试。

- 控件约束、候选依据、业务上下文或界面结构变化仍产生新样本。身份不明确的控件不跨状态抽样合并；疑似操作保持阻塞，不因抽样获得执行权限。
- Observation、UIState、Visit 和截图仍完整保存。抽样不是状态等价规则，也不改变严格检查点验证。
- `FrontierItem.sampling` 保存策略版本、依据及观察引用。未尝试的样本可移到当前符合抽样条件的观察，避免为无关输入值返回旧界面。
- 已尝试样本的 `action / stateId / attempts` 指向实际执行条件，后续观察不会把旧成功复制成新状态的成功。再次显式执行则记录新的真实尝试。
- 汇总的 complete 只表示已发现代表性样本全部 executed；调试页明确展示抽样范围，report 返回 exploration 和相应覆盖说明。动作执行成功仍不等于业务断言通过。
- 抽样策略使用 `browser-representative-v1`，后续策略升级必须显式区分版本，不得静默重算已有执行结果。

代表性模式的 maxDepth 按已观察的 URL / 弹层范围层级计算：同一页面填写多个字段不会不断增加层级，回到已知范围复用其较浅深度。原始访问路径的 `Visit.depth` 保留，另存 `explorationScope / explorationDepth`。逐状态模式保持原先的路径深度。动作和时间预算继续约束全部探索、退出、恢复及重置。

代表性模式默认排序优先界面操作，再尝试提交和未知副作用操作；当前弹层仍优先，外部 choose hook 可覆盖排序。逐状态模式保留原有 DFS 排序。再次进入已完成抽样的弹层时，可以执行必要退出操作；每个范围实例中同一无效退出不会反复执行。

## 局部恢复与环境重置

严格恢复顺序为：验证当前位置 → 退出并验证弹层 → 已记录的可重放路径 → 显式声明的局部逆操作 → 必要时环境重置 → 入口重放。观察不足、上下文改变或路径偏离继续返回相应非成功状态。没有退出当前弹层时，不通过重置绕过它。

浏览器会话配置，SDK、HTTP 和客户端共用：

```ts
{
  exploration: 'representative', // 或 'stateful'
  interfaceActions: [{ stableKey: 'id:known-local-button' }],
  reversible: [{ stableKey: 'id:local-draft-field', kind: 'fill' }],
  environmentReset: 'none', // 显式支持的另一值：'document-reload'
}
```

`interfaceActions` 是应用方对已知界面操作的声明，匹配字段与 exclude/replayable 相同。它允许已确认的操作作为界面动作重放；不能把真正的表单提交或疑似操作降为安全界面操作。仅设置 replayable 不会清除业务状态标记。

`reversible` 只为已声明的 fill/select/check 构造逆操作。目标必须身份唯一、约束匹配、当前可操作且不被排除；会话有未确认的业务副作用时不执行局部逆操作。每步使用统一执行器和预算，保存意图、结果和观察，并比较预期的完整可观察投影。出现额外变化立即返回 UNVERIFIED，不以“目标字段填回去了”代替恢复验证。仅凭 input/select 类型不会自动声明可逆。

`environmentReset: 'document-reload'` 表示调用方明确声明：相关业务状态全部存在于当前文档，重新打开入口会重置这些状态。它不清理 localStorage、cookie 或服务器数据，不适用于以这些位置保存业务状态的环境。重置通过正常动作账本执行，来源为 `recovery-reset`；完整观察成功后才清除 dirty 标记，目标检查点仍需独立验证。默认 none。真实业务继续使用 reset hook 执行实际环境重置并提交证据。

会话通过 `dirtyAttemptIds` 记录提交/未知操作的来源。`ReachResult.diagnostics` 包含检查过的恢复方式、仍未重置的 dirtyActions 和 resetAvailable；自动探索受阻时将其关联到待办的 recovery。调试页可以直接查看触发动作，不必猜测“业务状态可能已改变”的原因。旧记录缺少来源时不会伪造。

## 本地测试站

[测试站配置](../examples/test-site-profile.ts) 只针对本仓库 React fixture：声明 Rebuild inputs / Quick Market / Reset interface 的界面语义、普通字段的可逆性，并开启文档重置。调试页点击“使用测试站常规配置”启用；修改网址即解除这些声明。

常规范围覆盖订单类型、交易对、金额/价格、单位、开关、设置弹层和提交。持续刷新和重复控件歧义是独立专项场景，通过显式排除保留在报告中；疑似操作也保留为缺口。常规流程结束不表示全站或全部组合覆盖。

验收覆盖抽样减少待办、真实执行证据不被改写、约束/结构/上下文变化、旧会话语义、局部恢复及意外副作用、真实提交风险、重置账本、动作预算和测试站常规流程。后续的业务依赖声明、更细的结果复用、服务器分支隔离和边界/组合输入仍属于扩展工作。
