# 控件覆盖与可验证恢复

浏览器新会话默认使用 `exploration: 'controls'`，目标是覆盖遇到的控件及其支持的操作。`representative` 按代表性状态条件取样，`stateful` 保留逐状态探索。未保存 exploration 的旧会话及纯 core 的默认配置仍使用 stateful。

## 三种覆盖范围

| 模式 | 工作单位 | 适合的问题 |
| --- | --- | --- |
| controls（默认） | 控件、操作、目标样本、目标约束/选项、声明的上下文、页面/弹层范围 | 每个已发现控件是否实际操作过？ |
| representative | 上述条件加可见控件结构、有效性、按钮显示/展开状态等 | 代表性界面条件下是否执行过？ |
| stateful | 完整可观察状态下的独立动作 | 各状态组合下是否执行过？ |

控件覆盖不要求为了测试另一个按钮而恢复所有字段旧值。目标约束或声明的业务上下文改变仍会产生新的样本。可逆性、风险分类与覆盖范围是独立概念：未知按钮仍是 unknown，实际提交仍是 submission；默认没有业务重置权限。

`BrowserEngine.controlCoverage()` 和 `report.controlCoverage` 按观察与真实动作账本计算：

- `actionable / covered / incomplete`：遇到的可操作控件，以及各支持操作至少成功执行一次的情况；排除、禁用、未执行、失败或结果未知不会算作覆盖。
- `readOnly`：已观察的只读控件，不生成无意义的填入任务。
- `unconfirmed`：只有疑似交互依据或尚无支持操作的元素，保留为观察缺口。
- 每项带控件引用、观察引用、各操作的尝试记录。身份不明确的两个节点分别统计；不凭相同标签合并。仅观察节点可以通过同一文档内的实例连续性归组，持续变化的只读名称不会产生无穷多个控件。
- 带 supported 依据的外部操作判断计入对应观察/节点的支持操作；只有真实成功尝试才计入 covered。判断保留在动作记录中，不改写原始 DOM 能力；tentative 探测不升级为已确认操作。

这是“已遇到控件的操作覆盖”，不是所有输入组合、业务断言或尚未发现行为的证明。具体样本的完成情况继续通过 `frontierCoverage` 查看。报告经现有 HTTP `/report` 返回，客户端提供 `report()`；调试页显示两种计数。

## 调度、定位与稳定性

控件模式优先尚未操作的控件及当前滚动遍历，同等条件下先界面动作，后提交/未知动作。弹层内工作优先，退出前不切换父界面。控件和代表性模式按 URL/弹层范围计算 maxDepth，同页输入不累加层级；原始 Visit.depth 继续记录真实路径。全部探索、重新进入、退出、恢复和重置共用动作与时间预算。

同等优先级下先安排当前界面新出现的控件，再操作既有同级入口，减少非模态菜单被后续操作关闭而遗留工作。该排序不把普通展开区域认定为独占弹层，也不凭出现顺序建立可重放的入口关系。

搜索式下拉的语义列表可能只是虚拟滚动内容层。存在单一列表和兄弟搜索/关闭控件时，适配器可用它们共同的有限浮动面板作为边界，并记录 `composite-popup-panel` 依据。不会跨越已有弹层或页面地标，也不合并同一容器内的多个列表。搜索结果清空时，同一仍可见的面板继续约束交互；面板消失或节点替换后不沿用该关联。

如果逻辑身份有歧义，但当前观察中节点实例唯一，可以在 controls 模式按 `ActionCandidate.target` 执行。`identityResolved` 仍为 false，另以 `targetResolved` 记录当前定位成功。动作不能历史重放；执行前仍核对完整交互投影、当前观察、文档实例和实际节点。节点替换后旧候选失效，不把当前定位成功当成跨状态身份确认。

控件模式使用交互投影检查稳定性和执行前变化：保留支持操作的目标、值、约束、位置、可操作性、实例、页面及弹层；只读填入显示和仅疑似容器不阻止可交互区域收敛。声明的业务上下文仍独立复核。全量观察、截图和 UIState 保留原始变化；只读显示持续刷新时 stable 仍为 false，附带非致命 UNSTABLE / INTERACTION_STABLE 证据。可编辑目标变化、遮挡、节点替换、新弹层等仍令候选失效。严格检查点不会把这种局部稳定当作完整状态恢复。

再次进入已知弹层可以使用历史成功、可重放的界面入口；入口必须在当前观察中唯一匹配且可操作。进入后重新观察，再安排当前候选，记录 `exploration.scope_reentry`。这不声明恢复了旧业务状态。每项任务的重新进入尝试有界，仍受总预算限制。

部分弹层通过位于边界外的入口按钮关闭，却没有可识别的 DOM 关联。调用方可通过 actions hook 对具体点击添加 `supported` 的操作依据：`rule: 'declared-boundary-exit/v1'`，非空 `source`，以及 facts 中的当前 `observationId`、`localId`、`boundaryKey` 和非空字符串数组 `evidence`。同时必须明确 `risk: 'interface'`。适配器只为完全匹配当前观察、目标和最内层弹层的声明生成退出意图，不将任意外部候选的 boundary 字段当成依据。

声明不证明退出已经发生，也不提供历史重放权限。当前唯一定位、可见性、遮挡、排除和观察完整性限制仍生效；点击后弹层仍存在时，范围保持打开，背景工作继续阻止。原生表单提交不能通过该声明或 actions hook 降级为界面退出。原始观察中的 exitControlIds 不被修改。

恢复和遍历可以使用当次观察重新生成的退出声明，包括唯一定位但历史身份尚有歧义的当前节点；它们仍通过同一执行前验证。当前退出动作保持 `replayable: false`，不会因此进入历史重放路径。

滚动是遍历工作。适配器根据实际 CSS overflow 和可滚动尺寸发现元素内的滚动视口，排除文档根、文本编辑区及 overflow:hidden 裁剪容器。元素滚动绑定当前节点并检查遮挡，移动后确认实际滚动偏移变化；横向和纵向均按同一位置网格安排往返，避免尾页余量产生无穷偏移组合。滚动位置参与当前观察、过期检查和严格状态比较；虚拟内容不会成为无名滚动容器的名称。

当前视口变化后，同一页面范围内尚未执行、已不适用的旧滚动意图标记为 `superseded / traversal_position_changed`，保留“未执行”的证据；页面滚动和元素内滚动都从当前视口继续发现。它们不算成功，也不要求重置业务环境以还原历史滚动位置；其他真实控件的操作任务不会因此被取消。

同一文档的新完整观察确认弹层已不存在时，该弹层尚未尝试且不绑定真实控件的合成退出动作标记为 `superseded / boundary_already_exited`。它不计作执行成功，不为补做 Escape 而重新打开已关闭弹层；真实关闭控件的任务和已尝试动作保持原记录。

`FrontierItem.sampling` 记录策略版本（`browser-controls-v1` / `browser-representative-v1`）、依据和观察引用。未尝试样本可以更新到当前适用观察；已尝试记录保持实际执行条件，不复制成功证据。完整 Observation/UIState 和严格检查点等价规则仍独立于抽样策略。

## 严格恢复与环境重置

严格恢复顺序为：验证当前位置 → 退出并验证弹层 → 已记录的可重放路径 → 显式声明的局部逆操作 → 必要时环境重置 → 入口重放。观察不足、上下文改变或路径偏离返回非成功状态。没有退出当前弹层时，不通过重置绕过它。

```ts
{
  exploration: 'controls', // 或 representative / stateful
  interfaceActions: [{ stableKey: 'id:known-local-button' }],
  reversible: [{ stableKey: 'id:local-draft-field', kind: 'fill' }],
  environmentReset: 'none', // 显式支持的另一值：document-reload
}
```

这些都是可选的应用声明。`interfaceActions` 不能把真正提交或疑似操作降级为安全界面操作；仅设置 replayable 不会清除业务状态标记。`reversible` 只为明确声明的 fill/select/check 构造逆操作，要求身份唯一、约束匹配且当前可操作；存在未确认业务副作用时不执行。每一步比较预期的完整可观察投影，额外变化返回 UNVERIFIED。

`document-reload` 表示调用方明确声明相关业务状态全部位于当前文档。它不清理 localStorage、cookie 或服务器数据。重置计入账本，观察成功后才能清除 dirty 标记，检查点仍独立验证。真实业务环境使用 reset hook，并提供重置证据。默认 none。

`dirtyAttemptIds` 记录提交/未知操作的来源。`ReachResult.diagnostics` 给出检查过的恢复方式、dirtyActions 和 resetAvailable；调试页可查看触发动作。旧记录缺失的证据不会补造。

一次检查点恢复失败后，仍指向相同状态及上下文的 pending 任务共用这份失败结果，记录 `exploration.recovery_shared`，避免逐控件重复恢复。恢复期间已重绑到其他状态的任务不受影响；控件之后在完整观察中重新出现时，抽样任务仍可重新验证并继续执行。共用失败结果不表示这些操作已尝试。

## 验收与边界

完整 React 测试页使用通用默认控件模式、完整证据采集、无排除、无应用动作白名单、无可逆字段声明、无 reset hook。验收明确检查 19 个可操作控件（包括两个独立同名输入）全部实际执行，持续刷新的只读显示被观察，提交和未知动作保持原风险分类。测试另外修改名称、ID 和按钮顺序，验证同样结果。应用代码没有测试页专用分支或配置入口。

独立 HTML 验证持续只读刷新、可编辑目标变化、弹层变化、歧义节点替换、预算/排除/禁用缺口，以及滚动加载新控件。严格逐状态回归和显式局部恢复测试继续保留。

此能力不保证穷尽任意站点：无可识别入口、无限新增控件、不可逆分支互斥、未知自定义事件、iframe/Shadow DOM 等仍受实际发现与适配范围限制。服务器分支隔离、复杂恢复路径、业务依赖证明、边界输入和组合生成继续在 roadmap 中独立推进。

## 本地审阅工作台

`pnpm exec tsx --conditions=development scripts/exploration-workbench.ts URL OUTPUT_DIRECTORY` 启动通用工作台并输出本地 HTTP 地址。`GET /state`、`/summary`、`/screenshot`、`/hypotheses`、`/identities` 提供当前事实；`POST /command` 接受既有引擎命令。`POST /review` 接受当前 observationId、localId、kind、risk、reason、evidence 和可选 samples / replayable / exitBoundary，也可用 reviews 数组一次审核当前观察的多个控件。

操作审核只绑定同一文档、节点实例及业务描述，不自动跨重载复用。风险与 replayable 分别声明，重放默认关闭；引擎原有提交风险、身份歧义及弹层限制继续生效。审核记录追加到 reviews.jsonl，原始 DOM 观察不修改。身份裁决使用既有 resolveIdentity 命令；它不替代操作风险审核。工作台默认保留离页链接及未知用途动作的未审核缺口，不能据此宣称页面全部覆盖。

`exitBoundary` 必须是当前最内层弹层 key，并用于界面点击；工作台据此为相同实例生成上述当前观察退出声明。同一操作重新审核时采用最新记录，包括原始 DOM 没有生成操作的自定义控件。弹层关闭后声明不再授予背景操作额外权限，文档重载后需重新审核。
