# UI/UX 检查支撑实施计划

更新日期：2026-10-15。状态：设计计划，P0–P3 首版已在 codex/ui-inspection 实现，未合入 main；实际接口见 [检查 API](INSPECTION-API.md) 与末尾实现记录。以当前 `main` 的观察、弹层范围、详细证据和留存能力为基础；本文包含已实现与后续建议，不能把设计中的每个名称都视为已开放 API。

本文是 [Roadmap](../ROADMAP.md) 中 V0.2 检查支撑工作的实施契约。原 [V0.1 交付计划](../PLAN.md) 保留原范围。本文档更新在 `main`；后续代码实现从 `main` 创建独立的 `codex/` 分支。

## 1. 目标与边界

让外部 UI/UX 检查程序能够随探索持续工作：

1. 收到明确通知，知道何时检查、重点检查哪个范围、与哪次观察比较。
2. 通过稳定 ID 查询当时的结构、样式、空间、滚动和视觉证据，检查弹层本身及其对页面的影响。
3. 提前声明必需数据；证据不足时得到明确缺口及补采路径，不将缺失解释为通过。
4. 后续通过同一套契约接入中间态、画面帧和其他证据来源，不重建上层接入方式。

引擎负责观察、取证、身份、时序、交付与受控执行；检查规则、设计规范、业务预期及结论由上层提供。引擎不内置 LLM、提示词、模型管理或 Agent。外部规则示例用于验收接口，不改变这一分工。

“支持完成检查”限定为已声明能力、采集范围与预算内的证据契约。不能承诺任意页面、任意规则一定可判定，也不能从 CSS 自动推断全部产品意图。未知、截断、过期、不支持和不确定的关联必须可见。

## 2. 当前基础与缺口

当前主分支已有以下能力，实施时优先复用：

- 不可覆盖的 Observation、动作前后引用、交互图和范围进入/退出基线。
- 页面、控件、DOM、计算样式、矩形、截图、ARIA 和运行记录的历史查询。
- `observation.created` 的 reference / inline / hybrid 交付及 SDK / SSE 序号续读。
- 内存、SQLite 及留存装饰插件；TTL、容量、可用性、固定与释放。
- 弹层识别、嵌套与 Portal 归属、范围关闭后与父区域入口基线的比较。

计划制定时 main 尚未提供统一检查机会、采集需求协商、检查消费租约、检查结果关联协议，以及逐元素完整的滚动/盒模型测量和通用空间关系查询。现有控件语义差异不包含完整样式与几何差异。通用受控补采、等待外部检查的调度关卡和过程记录也未实现。

`hooks.check` 目前是动作后的进程内回调，有 5 秒超时；它不是跨进程长耗时检查协议。事件订阅当前不会阻塞探索。现有 `stable` 仅描述有界观察条件，不证明业务加载或所有视觉变化已经结束。

## 3. 核心决策

### 检查范围与证据范围分开

默认对当前交互范围完整检查，暂不要求精确识别变化节点。首次进入检查页面；打开弹层检查新弹层；弹层内操作检查当前弹层；关闭后检查恢复的父范围；嵌套时优先最内层。

检查范围只建议重点，不限制历史证据查询。对弹层的检查还应取得视口、页面滚动、祖先、内部滚动容器、焦点和相关层级等上下文。允许上层扩大范围，不能仅交付裁剪图或孤立 DOM 子树。

全页基础事实在预算内采集并保存，重点范围具备其声明检查所需的详细证据；较重数据按采集配置启用。不能把“按需查询”误实现成页面变化后才首次采集历史所需数据。

### 检查契约独立于交互状态归组

一次 UIState 可以对应多份检查证据。每次符合检查策略的新采集都可产生检查机会，不按现有语义指纹去掉颜色、尺寸、间距等变化。检查采集不能无条件扩大 UIState 等价字段、重建待办或改变恢复语义。

### 事实、派生测量与规则结论分开

原始尺寸和样式保留来源；推导的滚动/裁剪/遮挡关系标明方法、版本和限制；“不应撑大页面”等规范来自上层。命中点采样不能称为完整遮挡检测，没有 `max-height` 不能单独证明缺陷。

### 历史查询与新取证分开

查询不读实时页面、不滚动、不展开、不重放。缺失字段返回缺口；新取证创建新 capture，并关联原检查请求，不改写旧事实。需要动作的验证走同一个执行器及权限、预算、去重和恢复约束。

## 4. 对象与版本契约

| 对象 | 责任与最小字段 |
| --- | --- |
| Capture | 不可覆盖的证据集合：captureId、会话、文档/实例作用域、可选 observationId / attemptId、采集起止时间、阶段、采集配置版本、组件清单、质量和覆盖范围 |
| Inspection | 检查机会：inspectionId、协议版本、原因集合、当前 capture、对照引用、主范围及上下文引用、所需能力、就绪质量 |
| CaptureProfile | 上层取证需求：配置 ID/版本、必需/可选能力、范围、预算、稳定条件与缺口处理策略 |
| EvidenceComponent | 证据组件：带命名空间的类型、schema/采集器版本、独立时间、覆盖范围、存储引用及采集状态 |
| InspectionDelivery | 消费者交付记录：消费者 ID、检查 ID、游标、租约期限、接收/完成状态；不修改 Capture 原始内容 |
| InspectionResult | 上层结论：检查 ID、capture/目标引用、规则 ID/版本、pass / fail / inconclusive / unsupported、理由和证据引用 |

Capture 与 Observation 分离：第一版通常一一关联，现有 observation 查询保留兼容映射；后续中间帧可以没有 Observation、UIState 和 frontier。节点用 `captureId + document/frame scope + nodeId` 确定历史含义。控件跨观察对应可使用已有逻辑身份，但必须暴露歧义，不能把 DOM 实例 ID 当作跨重载身份。

对照引用至少区分：

- `previous`：上一次相关采集，用于单步比较。
- `scopeEntry`：进入当前交互范围前的父范围采集，用于退出后累计影响检查。
- `actionBefore`：实际动作前关联的采集，不暗示与鼠标事件同一瞬间。

基线记录 available / missing / incomparable 及原因。首次看到已经打开的弹层不伪造入口基线；跨导航、视口变化或身份歧义时不强行进行可比性推断。基线事实与当前留存可用性分别表达。

数据模型与事件载荷都带版本。新增证据类型不改变通用交付流程；旧客户端识别未知类型并报告未消费，不将未知能力当作已检查。旧观察只能投影其真实存在的能力，不能通过版本迁移伪造新字段。

## 5. 通知时机与范围策略

新增 `inspection.ready`，语义为检查记录和实际成功保存的证据已可查询；不代表页面一定稳定、证据全部齐全或检查已通过。

| 原因 | 主检查范围 | 必须关联的上下文 |
| --- | --- | --- |
| initial | 当前页面；若已有弹层则突出最内层 | 页面与视口、初始弹层链；入口基线可能缺失 |
| scope_entered | 新打开的最内层弹层/菜单等 | 打开前的页面、触发目标、父范围、页面滚动与焦点 |
| after_action | 操作后的当前范围 | 操作及前后 capture、页面全局指标 |
| scope_exited | 恢复后的父范围 | 入口基线、退出前与退出后 capture、关闭的范围 |
| navigation | 新文档 | 导航前引用、文档作用域变化及可比性限制 |
| observed_update / environment_changed | 当前范围，必要时页面 | 上一次相关采集、变化环境与发现方式 |
| manual | 上层指定范围 | 显式采集请求及原检查机会 |

第一版的异步更新指在显式观察、动作前检查或已有观察流程中发现的更新，不声称持续监听所有页面变化。后台变化监听及合并策略后续可增加，同样使用上述契约。

同一 capture、范围和配置版本下的多个原因合并，避免一次弹层打开生成重复检查任务。不同 capture 保留各自身份。范围识别不完整时扩大建议范围并附理由，不静默忽略无法分类的区域。

动作失败后若仍取得可用观察，也产生检查机会并附实际执行状态；完全无法采集时记录不完整结果。动作成功、证据就绪和检查通过不能互相替代。

生产顺序：确定范围与对照 → 采集/完成证据写入 → 检查能力覆盖与预留读取期限 → 提交检查记录和引用事件 → 交付通知。不得只在异步订阅者看到通知后才尝试保护证据；快速后续操作可能已使旧证据被淘汰。

异步二进制写入不属于当前同步记录事务：处理写入成功但记录提交失败、记录存在但部分写入失败，以及重启后的清理。缺口记录可交付；部分证据的 ready 不得伪装成全部必需数据可用。

## 6. 通用证据与能力声明

### 第一版常规检查数据

| 数据组 | 内容与约束 |
| --- | --- |
| 环境与页面 | 布局/可见视口边界及偏移、像素比例与缩放信息、页面与实际滚动元素、横纵滚动范围及位置、焦点与已知环境配置 |
| DOM 与语义 | 元素和文本节点、父子关系、属性、运行时状态、控件身份/歧义、label/ARIA、区域及弹层逻辑关系；不假设所有 UI 都是可操作控件 |
| 几何与盒模型 | 视口坐标矩形、边框/内边距等盒模型信息、client/scroll/offset 尺寸、滚动位置与坐标单位；变换和复杂布局导致的推导限制可见 |
| 样式 | 布局、尺寸与 min/max 约束、overflow、position、颜色、背景、字体、边框、透明度、变换和裁剪等版本化属性组；继续允许全部计算样式 |
| 空间关系 | DOM 祖先与逻辑归属分开；滚动/裁剪祖先及相关属性、弹层入口关系、既有命中采样及方法；Portal 不只依赖 DOM 父区域 |
| 视觉与运行上下文 | 视口截图及矩形映射、可选整页图、现有 ARIA/网络元数据/控制台/错误；组件各自计时，不冒充原子快照 |

测量值与文档、坐标系、滚动偏移及时间关联。visible、在视口内、被裁剪、命中测试结果分别表达。页面或容器可滚动不等于操作系统滚动条此刻可见，不能仅用像素宽度差断言滚动条出现。

重点范围包含整个所需子树，而非仅已发现控件。过长 popover 检查需要内部滚动子容器与相关祖先；全页概要和对照基线必须独立于弹层裁剪图存在。

### 可选与后续能力

文字行/片段矩形、伪元素、字体与图片加载详情、更精确的变换/裁剪关系、扩展可访问性证据、框架状态、画面帧和性能时序以版本化组件扩展。iframe、Shadow DOM、Canvas 的现有限制继续报告；预留接口不代表已经支持其内部。

计算样式不自动等于最终合成像素颜色；复杂背景、透明层、滤镜等需要视觉证据或额外能力。裁剪图只裁已保存画面，不声称包含视口外内容；整页截图也不承诺等同于同一时刻的用户视口。

### 先声明需求，再采集

上层在会话开始或后续新采集前提交 CaptureProfile，区分 required 与 optional 能力。例如布局规则声明 geometry、scroll-metrics、layout-styles、ancestor-relations；文字截断规则另外声明 text-fragments；视觉规则声明 viewport-image 和坐标映射。

分别报告三个维度：采集器支持哪些能力、本次实际采到哪些数据、这些数据目前是否仍可读取。节点数量、文本长度、字段、截图范围与帧覆盖均可形成缺口，不能用一个 complete 标志代替。

- 已知不支持的 required 能力：接受配置时拒绝或要求上层明确降级，不启动一个宣称可满足的检查任务。
- 运行时缺失 required 数据：保存事实和缺口，该规则不能 pass；strict 策略在下一个执行边界暂停，report 策略可继续探索并交付不完整检查机会。
- optional 数据缺失：继续交付，但上层能识别依赖该数据的规则未运行。
- 捕获后才新增需求：仅作用于新采集，不补写旧 Capture。

strict/report 只约束检查证据处理。已有执行所需的关键观察、身份或业务前提失败仍按原规则阻止动作，不能借 report 模式绕过。

第一版定义可扩展的采集器契约：类型/版本、输入配置、依赖、是否需要实时页面、可能副作用、预算及输出 schema。先实现内置空间采集器；后续服务进程安装自定义采集器，不开放远程任意脚本执行接口。

## 7. 查询与补采接口

以下是职责与建议命名，P0 需确定具体 schema 和 HTTP 映射；不是当前可调用接口。

| 接口 | 职责 |
| --- | --- |
| inspection / listInspections | 按 ID 或会话游标获取检查机会、原因、范围、基线与能力要求 |
| captureDetails | 环境、页面概要、组件清单、实际覆盖与留存状态 |
| queryNodes | 按 capture、根节点、字段组、深度和游标读取保存的树；普通节点与控件都可查询 |
| nodeContext / regionContext | 祖先、滚动/裁剪链、子区域、弹层和语义关系；区分已知关系与未采集目标 |
| captureArtifact | 获取指定组件的字节、类型、时间、坐标映射与完整性信息 |
| capabilities / validateProfile | 查询可采集能力并验证配置需求与预算；不等于本次数据必然存在 |
| completeInspection / renewInspection | 幂等记录消费者完成或续租；与传输游标分别管理 |
| requestCapture / requestProbe | 显式新取证命令；probe 实际执行留到后续阶段，不实现成历史 GET 的隐藏副作用 |

查询只返回已提交且属于该会话/capture 的内容。缺失区分 not_captured、unsupported、capture_truncated、query_limited，以及 expired/evicted/storage_failed 等留存状态。分页结束不表示原始采集完整。SDK 与 HTTP 暴露同一套语义。

原 observationDetails、controlDetails、regionDetails、dom、eventContext、evidenceArtifact 保持兼容。Capture 是可扩展证据标识，不强制迁移旧数据或删除原 Observation 查询。

## 8. 交付、租约与结果

默认异步消费：通知不等待上层检查完成，页面可以继续探索。快照不可覆盖，结果始终绑定历史 capture。传输复用 reference / inline / hybrid，事件日志保持引用，避免大图反复写入日志。

检查配置声明消费者和有限保留预算。生产端在发布前为已登记消费者预留有期限的保护；消费者续租有上限。晚加入者只能获得仍存在的证据，不承诺补回丢失历史。多消费者分别完成，一个消费者不能释放另一个仍持有的证据或入口基线。

优先扩展现有 owner/pin/unpin 和可用性清单，保护当前检查及所需基线。保留与调用方选择的实际 durability 一致，cache 不因租约而获得跨进程保证。transient 继续尽力交付；要求服务端可重复查询及基线保证的配置必须选择兼容留存方式，不静默升级语义。

租约到期、取消、消费者崩溃、容量不足和进程重启均有明确状态与事件。strict 配置在保证无法维持时暂停后续探索；report 配置可继续，但报告丢失/无法判断。固定内容计入容量，不为慢检查器创建无界缓存。

交付允许重试；消费者以 inspectionId + ruleId/version 等键去重。事件游标前进、网络成功发送、消费者接收和检查完成是不同状态。完成确认幂等，缺少结果不自动产生 pass；允许上层保留自己的报告，仅提交消费完成。

结果保留目标和证据引用。重复问题可由上层合并，但不因此删除新采集的检查机会。晚交结果仍属于旧 capture，不能作为当前页面的检查结论。

## 9. 执行协调与现场验证出口

第一版默认只读快照检查。完整等待外部检查与现场 probe 是后续能力，现在确定边界：

- 等待模式在下一次动作入场前建立关卡，不依赖收到事件后再发 pause 的竞态。
- 规定完成、超时、失败、取消后的继续/暂停策略；超时不等于通过，也不保证外部代码自动取消。
- 暂停动作不会冻结页面动画、网络和定时器。实时 probe 验证文档/目标时效，记录新采集时间；变化时返回新 capture 或明确失效。
- 滚动、聚焦、展开等验证动作声明副作用，使用统一动作账本和串行执行器；不假定执行后能无损恢复现场。
- 不在占用队列的 hook 内等待排在自己后面的补采命令。关卡允许指定取证请求执行，同时阻止普通探索动作，避免死锁和多执行器竞争。

新能力不能绕过已有请求去重、预算、身份歧义、业务前提及重放限制。

## 10. 中间态扩展契约

第一版保留 phase（settled / intermediate / timeout）、可选过程段 ID、动作引用、样本序号、时间窗口和组件覆盖。实际第一版交付首次/显式观察及操作后达到条件或超时的采集，能力清单明确 intermediate 尚未启用。

后续过程采集器在动作前、首次导航前启动，才能覆盖操作/加载过程；后台无动作更新也允许产生过程段，明确关联只是观察区间，不无依据断言由某操作引起。

- 一段操作关联多个不可覆盖的 Capture；样本可单独通知，最终样本不覆盖中间样本。
- 中间样本不必生成 UIState、Transition 或 frontier，避免把帧率变成探索工作量。
- 画面、DOM、几何与运行事件各自有时间、时钟来源和关联窗口；只有图片时不套用结束后的 DOM。
- 采样频率、开始/结束覆盖、已知丢帧、无法估算的缺口、容量和合并策略公开。没有采到不能证明没有闪烁或白屏。
- 使用相同的能力查询、历史查询、租约和结果协议，不要求消费者读取“最新页面”解释中间帧。

连续截图、录像、逐帧白屏/闪烁判定、性能时序采集本次均不实现。实施时间由独立预算和性能验收决定。

## 11. 分层与实施顺序

| 层 | 计划责任 |
| --- | --- |
| packages/adapter-playwright | 浏览器测量、文档/节点作用域、空间事实、采集器与浏览器能力限制 |
| packages/browser | Capture/Inspection 组合、范围与基线选择、能力配置、历史查询、检查消费协调 |
| packages/core | 复用观察/动作/范围生命周期、通用队列与事件；必要时补平台无关的完成边界或调度接口 |
| packages/storage-retained 及存储插件 | 扩展保护 owner、期限、容量与可用性；不解释 DOM 或 UI 规则 |
| apps/server / packages/client | HTTP/SSE 映射、类型、续读与取消 |
| apps/ui / examples / tests | 调试入口、外部检查器示例、端到端验收 |

保持 [现有依赖方向](ARCHITECTURE.md)。采集器、DOM 差异、HTTP 和视觉规则不加入纯 core。检查机会应在范围/基线与证据生命周期完成关联后发布，不能仅拼接原始事件监听回调并假定顺序成立。

### P0：冻结契约与兼容策略（V0.2）

- 确定对象、事件强类型、版本、查询/命令边界、缺口与能力状态。
- 明确 Capture 与旧 Observation 映射、范围策略、基线可比性、发布顺序及去重键。
- 确定 required/optional、strict/report 和租约边界；列出不兼容配置的拒绝条件。
- 形成公开 TypeScript 契约及示例载荷；中间态和 probe 的未支持状态可查询。

完成条件：同一份契约能描述初始页面、弹层打开/关闭、缺失基线和未来只有画面的中间样本，不改变原交互图语义。

### P1：补齐常规空间证据（V0.2）

- 内置采集器覆盖页面实际滚动元素、节点滚动尺寸、盒模型、约束样式和祖先关系。
- 保存全页基础上下文及重点子树，提供预算、覆盖、来源、坐标映射和缺口。
- 实现 Capture 查询及旧查询兼容；较重测量保持可选或明确未支持。

完成条件：外部程序不依赖实时页面或新增浏览器脚本，即可从保存数据检查过长 popover 的越界、内部滚动与页面滚动范围变化，并正确处理内部子节点承担滚动的合法实现。

### P2：检查机会与可靠交付（V0.2）

- 实现首次、动作后、范围进入/退出、导航和显式观察的范围选择与原因合并。
- 完成发布前保护、有限租约、幂等消费确认、容量/到期/重启处理及基线保护。
- 默认异步交付；strict 的证据不足在下一个动作边界暂停，不自动等待任意外部检查函数。

完成条件：快速连续操作、慢消费者及重复续读不会把历史目标混成最新页面，不静默失去已承诺保留的证据。

### P3：SDK/HTTP 接入与验收（V0.2）

- SDK 与 HTTP 暴露同样的检查、查询、能力和消费接口，保留现有事件兼容。
- 调试界面展示原因、主范围、基线、phase、缺口及期限，区分检查问题和采集失败。
- 提供无模型外部检查器示例：消费机会、查询空间数据、执行规则、返回证据化结论并确认消费。
- 更新 EVIDENCE-API、ARCHITECTURE、README 和验收记录；通过下面矩阵后再标为已实现。

### P4：取证扩展（后续，优先衔接 V0.3）

按实际规则需要增加自定义采集器、文字行/伪元素等证据、受控 probe 与等待检查模式，以及 iframe/Shadow DOM 等范围适配。中间态记录另立后续里程碑；当前仅保留契约。

## 12. 验收矩阵

以下是设计验收矩阵；开发分支首轮覆盖情况见末尾实现记录，未覆盖的更深适配与性能边界继续保留。使用本地测试站和外部确定性规则；产品规范由测试规则声明，核心不得硬编码场景标签。

| 场景 | 必须验证的结果 |
| --- | --- |
| 首次页面、初始已开弹层 | 创建会话后仍可续读机会；已有弹层没有入口基线时明确缺失 |
| 打开/操作/关闭 popover | 主范围分别是新弹层、当前弹层、父范围；入口与单步基线不混用 |
| 过长 popover 撑大页面 | 外部程序获得越界、内部容器与页面前后滚动数据，报告证据；不只依赖 max-height |
| 合法的内部滚动子容器 | 根 popover 没有 overflow 也不误报；根与子容器职责可区分 |
| 页面本来能滚动、滚动位置改变、背景异步变长 | 比较范围增量并归一坐标；只报告观察期间变化，不自动证明因果 |
| 文字截断、颜色变化、节点几何变化 | 能力存在时可检查；文字行等未提供时明确 unsupported/inconclusive；UIState 不变仍有机会 |
| 嵌套弹层与 Portal | 逻辑范围和实际 DOM/滚动祖先分别可查；关闭子层返回正确父范围 |
| 遮挡、裁剪、非控件内容 | 不局限于动作候选；采样遮挡不包装成完整遮挡结论 |
| 截断、禁用、超时、截图失败、导航中断 | 质量及规则缺口可查；返回空数组不能判断通过 |
| 查询旧 capture 时页面继续变化 | 不操作页面，不替换为最新值；缺数据只能新建采集 |
| 多消费者、断线续读、重复完成 | 幂等且保护相互独立，传输成功不等于检查完成 |
| 租约到期、容量耗尽、进程重启 | 明确失效/暂停/降级；不无限增长内存、不虚构缓存持久性 |
| 旧观察与未知组件版本 | 保留原始能力；旧调用兼容，未知组件不宣称已检查 |
| 未来中间态契约样本 | 允许仅画面、不同组件时间及无 observationId；不进入状态归组或生成待办 |

验证覆盖契约/规则单测、存储与 SDK/HTTP 集成、浏览器端到端以及分层约束。记录额外采集耗时、证据量、连续操作下内存和慢消费者行为；P0/P1 实测后确定默认预算，不以无界容量消除失败。

## 13. 本次不作为前置条件

- 精确全页视觉变化区域、仅检查变化节点、像素回归或完整可访问性审计。
- DOM 增量存储链；现有独立分块去重继续可用。
- 连续录像、瞬时闪烁/白屏检测、全帧无遗漏保证。
- 全站/全业务覆盖、跨页面完整身份推断、恢复完整服务器世界。
- 多会话、远程存储协议、上传下载等无直接依赖的浏览器扩展。

这些工作保持在 Roadmap 的后续条目中。V0.2 首先交付稳定检查入口、可查且足够表达常规布局事实的证据，以及明确的数据不足处理；不把尚未实现的优化写成已有保证。

## 14. 首轮实现记录（codex/ui-inspection）
